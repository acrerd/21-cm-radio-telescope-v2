# Plan: browser (HTML/JavaScript) version of the dish simulator

Status: **implemented** (M0–M5 complete, golden suite all green —
see README.md for usage). This document is the design record.
This folder will hold a static, install-free web version of
`../astro_simulator.py`, restricted by design to the **compact
datasets only** (`hi4pi_compact.npz.xz`, `continuum_1420_compact.npz.xz`).
No full-cube support, no downloads of the 33 GiB survey, no code paths
that reach outside this folder's data bundles.

## 1. Goal and non-goals

**Goal.** One static page that reproduces the desktop simulator's
behaviour on the compact data: click the all-sky map, get the
beam-weighted H I spectrum with continuum and radiometer noise; drift
scans on the continuum map; site visibility overlays; the Realise
button against the real controller. Served from any static file host
(or `python -m http.server`), usable on a laptop or the observatory
tablet, nothing to install.

**Non-goals (deliberate restrictions).**
- No full HI4PI cube: the minimum beam is the compact floor
  (`sqrt(1.0² + (2.355·0.5)²) ≈ 1.54°`), hard-clamped in the UI.
- No dataset downloads or upgrades at runtime; the two data bundles in
  this folder are the entire sky.
- Bands beyond the compact velocity coverage (|v| ≤ ~469 km/s about
  1420.406 MHz) degrade gracefully to continuum + noise only, exactly
  as the desktop code's empty-band path does — but never trigger a
  "use the full cube" suggestion.
- No build toolchain: plain ES modules, no bundler, no npm at runtime.

## 3. Data pipeline (`make_web_data.py`)

Measured facts that drive the format (radioconda python, 2026-08-09):
the compact cube is int16, shape (729 v × 360 lat × 720 lon), 378 MB
dense — too much for tablets. True sparsity is 16.7 % nonzero
(63 MB of values); per-pixel nonzero **segments** average 14 (median 8,
p99 71), so a multi-run sparse layout costs ~80 MB in RAM and gzips to
~24 MB (measured ratio 0.30 on the value stream).

**Cube bundle `hi4pi_web.bin.gz`** — little-endian, pixel-major so one
pointing reads contiguous spectra:

| section | type | content |
|---|---|---|
| header | JSON (length-prefixed) | shape, scale (K/step), fwhm, v₀/dv, lon/lat grid params |
| `pix_off` | uint32[nlat·nlon + 1] | cumulative run count per pixel |
| `runs` | uint16[2·nruns] | (k0, len) pairs per run |
| `vals` | int16[nnz] | concatenated nonzero T_B steps |

Decoded once at load into three typed arrays; the per-query engine
never touches compressed data again. Decompression uses the browser's
native `DecompressionStream('gzip')` (Chrome 80+, Firefox 113+,
Safari 16.4+ — the observatory browsers qualify; no pako fallback).

**Continuum bundle**: dense float32 360×720 + t_zero + fwhm (1.0 MB
raw, ~0.5 MB gzipped).

**N_HI display map**: *derived from the cube itself* at conversion
time (`N_HI = 1.823e18 · ΣT·Δv`), not from `nhi_grid_cache.npy`, so
the web version depends on nothing outside the compact data. It ships
inside `meta.json`-referenced section of the continuum bundle (float32
360×720, log-displayed). Differences from the HEALPix-derived desktop
map (velocity trim, 3σ zeroing) are cosmetic at display stretch.

## 4. Spectrum engine (`skydata.js`)

Direct port of `DishSimulator.spectrum/_finish/continuum` with the
compact-only branches kept and the full-cube branches deleted:

- Footprint: rows within `rmax = 1.5·eff` of b, columns within
  `rmax/cos(b)` with the same 0.05 cos floor and l-wrap; subsample
  `step = max(1, fwhm/(15·pix))`.
- Residual beam: `eff = sqrt(fwhm² − 1.0²)`, `sigma = eff/2.355`;
  weights `exp(−0.5(sep/sigma)²)·cos(lat)`; haversine separation.
- Accumulate per pixel: for each run, `acc[k0..k0+len) += w·vals`;
  divide by Σw, times η. (No NaN handling needed — the compact cube
  has none; the desktop NaN path is full-cube only.)
- Channel rebinning: `nchan` set → interp onto uniform grid with
  zero fill outside coverage, `df = bw/nchan`; else native channels.
- Continuum: analytic point sources (antenna theorem,
  `A_e·Ω_A = λ²`, Gaussian in separation) + beam-weighted diffuse map
  with its own residual-sigma floor (`max(…, 0.3·pix)`), plus t_zero.
- Noise: per-channel σ(ν) = (T_sys + T_cont + T_line(ν))/√(n_pol·Δf·τ);
  T_sys empty = noise off, T_sys 0 = ideal receiver (self-noise only) —
  mirror the 2026-08-09 semantics exactly. RNG: `xoshiro128**` seeded
  per page load (JS lacks a seedable stdlib RNG; seedability matters
  for the test harness, which injects a fixed seed).
- Drift scan: sample the great-circle track at the sidereal rate
  (RA advance 15.041°/h), band-average noiseless spectra, then add
  per-sample σ = (T_sys + T̄_A(t))/√(n_pol·BW·τ) with the same
  τ-per-sample rule and 20 000-sample display cap.

## 5. Map rendering (`map.js`)

- Offscreen 720×360 image per map mode (N_HI log stretch 4e19–2e22;
  continuum log 0.05–60 K), then one precomputed inverse-Mollweide
  lookup table (canvas pixel → lon/lat → grid index) built per resize;
  redraw is a single putImageData + overlay pass.
- Overlays, all ported 1:1: never-rises and alt<20° declination loops,
  the live horizon + zenith redrawn each minute, continuum source
  markers (Sun/Moon at load-time positions), M31 landmark, beam
  circle with cos(b) widening and l-wrap splitting, drift-scan track,
  legend, cursor l/b readout, click → point.
- Targets menu: same 18 pointings + 5 continuum sources, never-rises
  greying, description column; an HTML `<select>`-free dropdown panel
  matching the desktop list (plain positioned `<div>`).

## 6. Coordinates and ephemeris (`coordinates.js`, `ephemeris.js`)

Ported from the already-validated in-repo implementations
(`esp32_controller_arduino/src/coordinates.cpp` and
`test_coordinates.ipynb`, both checked against astropy to ≲0.5′):
Julian date, GMST (IAU 1982), precession (IAU 1976, both directions),
galactic↔equatorial (J2000 pole constants), RA/Dec↔Alt/Az, Meeus Sun
(~0.01°) and Moon (~0.3°, topocentric parallax correction added —
the desktop uses astropy's location-aware Moon; Meeus + parallax
matches to well under the 1° source-marker scale).

New ports this project adds:
- **LSR apex**: 20 km/s toward RA 18h Dec +30° (B1900) — precess the
  apex B1900→J2000 once (constants inline), then
  `dv_ssb = −20 km/s · cos(sep(apex, target))`.
- **Topocentric offset**: barycentric correction ≈ Earth orbital
  velocity (Meeus: derivative of solar longitude, e≈0.0167 ellipse,
  ~±30 m/s accuracy vs astropy) + diurnal term
  (0.4651·cos(lat)·cos(δ)·sin(H) km/s). Error budget ≲40 m/s ≈ 1/30
  of a native channel — acceptable, stated in README.
- **Cas A secular fade**: 2500·exp(−0.00670·(year−1965)) Jy, from the
  same constants as the desktop.

## 7. UI (`ui.js`, `index.html`)

Same layout grammar as the desktop: map above, spectrum/drift panel
below, control column left, one parameter row at the bottom —
`l, b, beam, BW, f_c, channels, T_sys, τ` — plus Targets / Map toggle /
Frame / Realise / scan-length. Behaviour parity checklist:

- channels box pre-filled with the band's native count; empty = native;
  clamp 2–65536; stepped (`steps-mid`) spectrum drawing.
- f_c display-precision rule (2 dp shown, exact value kept; typing a
  value that rounds to the rest frequency snaps to it).
- clamp-and-write-back on every box, with console-style message area
  replacing the terminal prints.
- frame button cycles LSR/SSB/Topo, relabelling only.
- σ₀ (line-free baseline) in the title; peak/continuum readouts.
- wheel zoom about the cursor on the spectrum; `s` saves PNG + txt
  (canvas `toBlob` + generated text download).
- Home button resets parameters and view (no matplotlib toolbar; a
  small custom button set: home, save).
- live RA/Dec + Alt/Az pointing readout, 1 s tick.
- **Realise**: `fetch()` to the controller
  (`/track/galactic`, `/tracking/enable`, `/direct`), default
  `http://192.168.106.120`, overridable by `?controller=` URL param.
  Requires a CORS header on the ESP32 (`Access-Control-Allow-Origin`)
  — a one-line addition to `web_server.cpp` shipped separately;
  until then the button reports the CORS failure clearly. (Serving
  this page *from the scheduler* Flask app is a later option that
  sidesteps CORS entirely; the page stays static either way.)
- site: Glasgow defaults from `meta.json`; `?lat=&lon=&height=&site=`
  URL parameters replace the CLI flags.

## 8. Validation (`gen_golden.py`, `test/run_golden.mjs`)

`gen_golden.py` imports the desktop simulator (radioconda python) and
writes `golden.json`:
- 12 spectra (noise off) spanning: plane/anticentre/high-lat/M31/LMC
  pointings × beams {1.6°, 4.93°, 10°} × bands {2 MHz native,
  5 MHz/1024 ch, off-line band} — full arrays.
- continuum T_A at 8 pointings including on-source (Cas A, Sun).
- frame offsets (SSB and topo at a **fixed** epoch passed explicitly).
- drift-scan T̄(t) arrays (noise off) for two targets.
- coordinate round-trips at fixed epochs.

`run_golden.mjs` (node ≥18, dev-only) loads the bundles + golden.json
and asserts: spectra max |ΔT| < 1 mK (identical arithmetic path);
continuum < 0.5 %; frame offsets < 40 m/s; drift arrays < 1 mK.
Noise paths are tested statistically (seeded RNG, σ within 2 %).

## 9. Performance and size budget

| item | budget | basis |
|---|---|---|
| download | ~25 MB total | measured gzip of bundles |
| RAM (decoded cube) | ~80 MB | measured sparse layout |
| load-to-interactive | < 5 s desktop, < 10 s tablet | decompress + decode + LUT |
| click → spectrum | < 50 ms | ~10³ px × mean 14 runs |
| drift scan (240 min) | < 1 s | ~200 spectra |
| map redraw | < 30 ms | LUT + putImageData |

## 10. Phasing

| phase | content | acceptance |
|---|---|---|
| M0 | `make_web_data.py`, format decode in node | round-trip equals npz arrays exactly |
| M1 | `coordinates.js` + `ephemeris.js` | golden coordinate/frame tests pass |
| M2 | `skydata.js` engine | golden spectra/continuum/drift pass |
| M3 | `map.js` + basic click→spectrum page | visual parity screenshot review |
| M4 | full UI parity (params, frames, drift, noise, save) | behaviour checklist §7 all green |
| M5 | Realise + CORS note, README, polish | bench test against controller or due_emulator |

Estimated effort: M0–M2 ≈ 1 day (mechanical, test-driven); M3–M4 ≈ 2
days (the bulk: canvas UI); M5 ≈ half a day. Each phase lands
committable and testable on its own.

## 11. Risks

- **Tablet RAM** (~80 MB decoded + page): within iPad/Android Chrome
  limits; if it ever pinches, the run bookkeeping can drop to uint8
  lengths (p99 run count fits) for −7 MB, or the cube can be halved to
  1° pixels — decision deferred, not needed on current numbers.
- **Ephemeris drift vs astropy**: bounded and stated (§6); nothing in
  the UI claims better than the beam width.
- **Float determinism** (JS float64 vs numpy float64): identical IEEE
  arithmetic; golden tolerances above are generous for ordering
  differences in summation.
- **CORS on Realise**: known, documented, two clean fixes (§7).
- **No-build ES modules need http(s)**, not `file://` — README states
  the one-liner (`python -m http.server`) and notes the scheduler
  could serve the folder later.
