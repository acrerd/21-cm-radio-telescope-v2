\begin{abstract}
This document is the definitive technical description of the Small Radio Telescope (SRT) drive and control system used for 21\,cm hydrogen line observations at Acre Road Observatory, Glasgow. The system comprises an Arduino Due carrying out real-time motor control, a WT32-ETH01 (ESP32) controller performing astronomical coordinate transformation, pointing correction and network service, a GNU~Radio receiver, and a Flask observation scheduler that also runs the pointing calibration. The document covers the hardware, the firmware on both microcontrollers, the coordinate and pointing mathematics in full, the resident pointing model and the Sun-scan calibration that determines it, the private Ethernet link between the observatory computer and the controller, the receiver and scheduler, and the installation, operation and fault-finding procedures.
\end{abstract}

\section{Introduction}
%==============================================================================

\subsection{Purpose and scope}

The SRT drive controller is a complete control system for an alt-azimuth mounted radio telescope observing at 1420.405\,MHz. It supports:

\begin{itemize}
    \item Real-time telescope positioning from a web interface
    \item Integration with planetarium software (Stellarium)
    \item Conversion between celestial and horizontal coordinates, with atmospheric refraction and a fitted mount pointing model applied
    \item Measurement of the pointing model from raster scans of the Sun
    \item Scheduled observations with automatic data acquisition
    \item Sun, Moon, galactic-plane and satellite tracking
\end{itemize}

This document describes the system as it now stands. Where a design decision is non-obvious the reasoning is given, because several of them were reached the hard way and are easy to undo by accident.

\subsection{System overview}
\index{system overview}

The system separates concerns across four processing units and one host computer:

\begin{enumerate}
    \item \textbf{Arduino Due} --- low-level motor control, encoder counting, limit-switch homing, current sensing and fault handling. It works exclusively in \emph{drive} coordinates.
    \item \textbf{WT32-ETH01 controller} --- network interface, astronomical transforms, the resident pointing model, web server and Stellarium protocol. It is the boundary between the sky and the mount.
    \item \textbf{H1 receiver} --- GNU~Radio spectrometer for 21\,cm data acquisition.
    \item \textbf{Observation scheduler} --- Flask application coordinating pointing and recording, and hosting the Sun-scan calibration.
    \item \textbf{Observatory computer} --- runs the receiver and the scheduler, and owns a private Ethernet link to the controller on which it provides the address, DNS and a route to the internet.
\end{enumerate}

A fifth component, the \textbf{sky simulator}\index{sky simulator} (Section~\ref{sec:simulator}), is not part of the observing chain but predicts what the instrument should see and can hand a simulated pointing to the real telescope.

\subsection{Two coordinate frames}
\label{sec:two-frames}
\index{coordinate frames}\index{coordinate frames!drive}\index{coordinate frames!true}\index{drive frame|see{coordinate frames}}\index{true frame|see{coordinate frames}}

One distinction runs through the whole system and is worth stating before anything else.

\begin{description}[style=nextline]
    \item[True alt/az] Where the dish looks on the sky. Every astronomical quantity is computed in this frame, using the true site latitude and longitude.
    \item[Drive] What the mount mechanically is: encoder pulses counted from the limit switches, quantised to $0.5^\circ$. The Arduino Due works only in this frame.
\end{description}

The two are joined by the transform in Section~\ref{sec:pointing}, which applies atmospheric refraction and the fitted pointing model. Every commanded position crosses from true to drive on its way out; every \emph{measured} position crosses from drive to true on its way back. Arrival and slew-completion tests are made wholly within the drive frame, so the two never mix.

\subsection{Data flow}
\index{data flow}

A typical observation proceeds as follows:

\begin{enumerate}
    \item The user or scheduler specifies a target (RA/Dec, galactic, alt/az, solar-system object, or TLE).
    \item The controller converts the target to \emph{true} alt/az for the current sidereal time.
    \item The observing horizon is tested against the true altitude.
    \item \texttt{trueToDrive()} applies refraction and the pointing model, producing a \emph{drive} position.
    \item The drive position is tested and clamped against the mechanical mount limits, then sent to the Due over UART.
    \item The Due computes a motion profile and drives the motors under PWM; reed-switch encoders count position.
    \item The Due reports drive position, motor currents and status once a second.
    \item The controller publishes the drive position as it stands, and its \texttt{driveToTrue()} image as the sky position, from which RA/Dec and galactic coordinates are derived.
    \item Once the slew has completed, the scheduler starts the receiver and data is written to HDF5.
\end{enumerate}

\subsection{Motor drive system}
\index{motors}

\subsubsection{H-bridge motor drivers}
\index{H-bridge drivers}\index{fault flags}

Each axis is driven by an H-bridge module with:

\begin{itemize}
    \item Two fault flag outputs (FF1, FF2) encoding the fault type (Table~\ref{tab:faults})
    \item An active-low reset input, held HIGH to enable the driver
    \item Inverted PWM speed control: 255 is stopped, 0 is full speed
    \item A single direction input
\end{itemize}

The fault outputs are electrically noisy at motor start and stop, because of inductive kickback and supply sag. \texttt{checkFaultFlags()} therefore requires the same fault to be present on \texttt{FAULT\_FLAG\_PERSIST\_COUNT} (5) consecutive calls before reporting it.

\subsubsection{Position encoders}
\index{encoders}\index{encoders!reed switch}\index{encoders!debounce}\index{PULSES PER DEGREE@\texttt{PULSES\_PER\_DEGREE}}

Position feedback comes from reed-switch encoders on each axis:

\begin{itemize}
    \item Resolution \texttt{PULSES\_PER\_DEGREE} = 2, i.e.\ a $0.5^\circ$ quantum
    \item Falling-edge interrupts; direction is inferred from the static direction pin at the moment of the pulse
    \item Debounce windows of 50\,ms (azimuth) and 100\,ms (altitude), both settable
\end{itemize}

The debounce timestamp is updated \emph{only} on pulses that pass the window. Updating it on every edge --- the original implementation --- caused total pulse loss as the motor speed approached the debounce interval, because every bounce reset the timer and no edge ever counted. This must not be reintroduced.

\subsubsection{Current sensing}
\index{current sensing}\index{current sensing!hall-effect sensors}\index{current sensing!filtering}\index{overcurrent}

Motor current is measured by hall-effect sensors read through the Due's 12-bit ADC against its 3.3\,V reference. The sensors are bipolar with a mid-rail zero, so

\begin{equation}
V = \frac{V_\text{ref}}{2^{12}}\,N_\text{ADC},
\qquad
I = \frac{V - V_\text{offset}}{S},
\end{equation}

with $V_\text{ref} = 3.3$\,V, a nominal $V_\text{offset} = 1.65$\,V and sensitivity $S = 0.044$\,V/A.

Two refinements matter. First, the reported current is a single-pole low-pass filter of the raw reading,
\begin{equation}
I_k = I_{k-1} + \alpha\,(I^\text{raw}_k - I_{k-1}), \qquad \alpha = 0.02,
\end{equation}
and it is the \emph{filtered} value, never the raw one, that \texttt{checkCurrentLimits()} tests --- otherwise a single ADC excursion trips an overcurrent fault. Second, the zero offset is re-tracked continuously while an axis is idle,
\begin{equation}
V^\text{offset}_k = V^\text{offset}_{k-1} + \beta\,(V_k - V^\text{offset}_{k-1}), \qquad \beta = 0.005,
\end{equation}
so long-term drift of the hall sensor settles towards zero by itself. The offsets are additionally measured directly at startup, by averaging 50 samples with the motors off.

\section{Arduino Due firmware}
\label{sec:due-firmware}
\index{drive firmware}
%==============================================================================

\subsection{Firmware overview}

The drive firmware (\texttt{src/main.cpp}) is a single bare-metal translation unit implementing:

\begin{itemize}
    \item An automatic three-phase homing sequence at power-on
    \item Ramped motion profiles that prevent structural oscillation
    \item Interrupt-driven encoder position tracking
    \item Safety monitoring: overcurrent, stall, limit switches, driver fault flags
    \item A line-oriented serial command interface on both ports
    \item Configuration persistence to flash via DueFlashStorage
\end{itemize}

Position is held in encoder pulses. Displayed degrees are $\text{position}/\texttt{PULSES\_PER\_DEGREE}$, and pulse position 0 is the hardware lower limit on each axis. After homing, both axes read $(0,0)$.

\begin{description}
    \item[INIT] Hardware initialisation, GPIO configuration, current-sensor zeroing, driver enable. Reported as \texttt{Initializing}.
    \item[HOMING] Running the homing sequence. Reported as \texttt{Homing}.
    \item[IDLE] Accepting commands. Reported as \texttt{Ready}.
    \item[DRIVING] Slewing. Reported as \texttt{Slewing}, or \texttt{Reversing} while an axis is decelerating to change direction.
    \item[FAULT] Motors disabled; reported as \texttt{FAULT} with the fault text in brackets.
\end{description}

The motion controller \texttt{updateAxisMotion()} runs from the main loop except in HOMING and FAULT. The IDLE$\rightarrow$DRIVING transition fires \emph{only} when a new-target flag has been set by \texttt{executeDrive()}. Without that condition the controller would chase stray encoder pulses while idle and could walk itself into a limit switch.

\subsection{Homing sequence}
\label{sec:homing}
\index{homing}\index{homing!three-phase sequence}\index{encoder origin}

Homing establishes the encoder origin in three phases, because a single fast run into the stop leaves an origin that depends on how fast the axis was travelling when it hit.

\begin{enumerate}
    \item \textbf{Drive to limits.} Both axes ramp up to full speed and run negative into the hard stops. An axis is judged to have arrived when no encoder pulse has been seen for \texttt{stallTimeoutMs} (2\,s by default).
    \item \textbf{Back off.} Both axes reverse $5^\circ$ under the same ramp profile.
    \item \textbf{Re-approach.} Both axes run into the stops again over the short remaining distance, so the approach is slow and the zero is repeatable.
\end{enumerate}

Both helpers obtain their profile from \texttt{calculatePWM(INT32\_MAX, startTime)}, which yields the standard ramp-up without ever entering the ramp-down branch. After phase 3 both position counters are set to zero. The mount then drives to the configured home offset,
\begin{equation}
n_\text{home} = \texttt{cfg.homeAz} \times \texttt{PULSES\_PER\_DEGREE},
\end{equation}
computed directly from the home angle --- the software minimum is \emph{not} subtracted --- and the position counters are set to the home coordinates. Both \texttt{homeAlt} and \texttt{homeAz} default to $0^\circ$, so by default the mount finishes homing sitting on its origin. A fault flag, overcurrent condition or unresponsive motor at any point aborts homing into FAULT. The whole sequence takes 30--60\,s depending on the starting position.

\subsection{Motion profiles}
\index{motion profiles}

PWM values are inverted: $\text{PWM}=255$ is stopped, $\text{PWM}=0$ is full speed, and \texttt{PWM\_MIN\_SPEED} $=100$ is the slowest usable drive. In the expressions below a \emph{smaller} number is a faster motor.

\subsubsection{Acceleration ramp}
\index{ramps!acceleration}\index{PWM}\index{PWM!inverted convention}

For the first $T_\text{ramp}$ milliseconds of a slew (\texttt{RAMPUP}, default 500\,ms) the PWM value interpolates linearly from the minimum speed to full speed:

\begin{equation}
\text{PWM}(t) = \text{PWM}_\text{min} - \frac{t}{T_\text{ramp}}\bigl(\text{PWM}_\text{min} - \text{PWM}_\text{full}\bigr)
             = 100\left(1 - \frac{t}{T_\text{ramp}}\right).
\end{equation}

Thereafter the axis cruises at $\text{PWM}_\text{full}=0$.

\subsubsection{Deceleration ramp}
\index{ramps!deceleration}

Deceleration is keyed to the number of encoder pulses remaining, $n$, and begins when $n$ falls below $n_\text{ramp} = \texttt{RAMPDOWN} \times \texttt{PULSES\_PER\_DEGREE}$ (default $7^\circ$, so 14 pulses):

\begin{equation}
\text{PWM}(n) = \min\bigl(\text{PWM}_\text{min},\; \max(\text{PWM}_\text{full},\; 218 - n^2)\bigr).
\end{equation}

The quadratic in $n$ gives an approximately constant deceleration in position; the clamp at $\text{PWM}_\text{min}$ stops the axis creeping so slowly in the last degree that the encoder debounce swallows its pulses. \texttt{STOPRAMP} (default 300\,ms) is the corresponding deceleration time applied before an axis reverses direction.

\subsection{Stall and limit handling}
\index{stall detection}

A stall is declared only when \emph{both}
\begin{equation}
t - t_\text{drive start} > T_\text{stall}
\qquad\text{and}\qquad
t - t_\text{last pulse} > T_\text{stall}
\end{equation}
are satisfied. The first condition matters: without it a stale \texttt{lastPulse} left over from a long idle period would trigger a false stall the instant a new slew began.

A stall that occurs while driving negative and within $2^\circ$ of the hardware limit is not a fault --- it is the limit switch. The position snaps to the limit value, the target is clamped, and the axis returns to idle. This is how the mount recovers gracefully from a commanded position slightly outside its range.

\subsection{Status output format}
\index{status line}\index{status line!format}\index{status line!de-duplication}\index{status line!rate limiting}

{\footnotesize
\begin{verbatim}
Alt:%.1f Az:%.1f Ialt:%.1fA Iaz:%.1fA Status:<state> [<fault>] -> Alt:%.1f Az:%.1f Cal:ON|OFF
\end{verbatim}
}

The \texttt{[<fault>]} group appears only in FAULT, and the \texttt{-> Alt: Az:} group only while DRIVING.

\begin{lstlisting}[language=bash,caption={Status output examples}]
Alt:45.0 Az:180.0 Ialt:0.5A Iaz:0.4A Status:Ready Cal:OFF
Alt:30.0 Az:150.0 Ialt:2.1A Iaz:1.9A Status:Slewing -> Alt:45.0 Az:180.0 Cal:OFF
Alt:30.0 Az:150.0 Ialt:5.2A Iaz:0.0A Status:FAULT [Altitude motor overcurrent] Cal:OFF
\end{lstlisting}

Two independent output disciplines apply.

\begin{description}[style=nextline]
    \item[Programming-port de-duplication] \texttt{outputStatus()} builds a comparison string that excludes the live current readings and prints to the USB port only when that string changes. Without it the port would emit a line per main-loop pass with nothing but ADC noise varying.
    \item[Serial1 rate limiting] The unsolicited line to the controller is emitted at most once per \texttt{STATUS\_INTERVAL\_MS} (1\,s). It used to be unconditional, which meant roughly 100 lines per second, about 6.5\,kB/s, into a receiver that drains five lines a second through a 256-byte buffer. That buffer was in permanent overflow, so bytes were dropped mid-line and the tail of one line arrived welded to the head of the next --- splices that still passed the controller's format check and parsed into plausible-looking nonsense. A \texttt{STATUS} command arriving on Serial1 is answered immediately on its own path and is not rate limited, and that is how the controller actually polls.
\end{description}

A \texttt{STATUS} command received on Serial1 is answered only on Serial1, and never disturbs the programming-port de-duplication buffer.

Three distinctions in that table are load-bearing and have each been merged by mistake at least once.

\begin{description}[style=nextline]
    \item[Observing horizon versus mount limits] \texttt{horizon\_alt} is a question about the sky --- has the source cleared the trees --- so it is tested against the target's \emph{true} altitude, before the pointing transform. \texttt{mount\_alt\_min} is a question about the machine, and clamps the \emph{drive} altitude afterwards. They were once merged into a single ``effective tracking horizon'' equal to the larger of the two, which quietly reinterpreted a mechanical stop as a sky horizon and left neither testable on its own.
    \item[Stow versus the Due's home] \texttt{stow\_alt}/\texttt{stow\_az} is where the dish \emph{parks}. It is the one sky-looking setting held in \emph{drive} coordinates, and the pointing model is deliberately bypassed on the stow path. Parking is mechanical --- ``leave the mount here'' --- not an observation, and at the default zenith stow the distinction is not academic: azimuth is degenerate there, every azimuth points at the same piece of sky, and the model's $\tan h$ azimuth term asks for a correction of order $50^\circ$ that would move the beam by exactly nothing. Through the model the dish would park at drive azimuth $170^\circ$. The Due's \texttt{HOMEALT}/\texttt{HOMEAZ} are also drive coordinates but mean something different again: the \emph{encoder origin}, what the limit-switch stall corresponds to.
    \item[Operator offset versus calibration] The \texttt{/offset} boxes are a deliberate sky-frame displacement layered on top of the calibration --- for raster mapping and beam switching --- and never a substitute for it. The offset is applied in the true frame, before the model\index{pointing offset, operator}, so ``$0.5^\circ$ off source'' means half a degree on the sky at any elevation.
\end{description}

\subsubsection{Clock discipline}
\index{clock}\index{NTP}\index{time synchronisation}\index{clock!error as pointing error}

The lwIP SNTP client polls in the background every hour; nothing blocks waiting for it. Success is declared only by the \texttt{onTimeSync()} callback, so a clock that has never been set cannot report itself as synced. \texttt{/time/status} publishes \texttt{sync\_state}, \texttt{stale}, \texttt{last\_sync\_age\_s} (which is $-1$, not 0, when no sync has ever happened), \texttt{last\_offset\_ms} and \texttt{sync\_count}. A browser-set time is recorded as source \texttt{browser} and deliberately does \emph{not} update the last-sync epoch, so it reports as unverified rather than masquerading as a checked clock.

Clock accuracy is a pointing specification, not a convenience. An error of $\tau$ seconds in UTC appears directly as an hour-angle error of $15.041\,\tau$ arcseconds, so the mount loses half an encoder quantum ($0.25^\circ$) after only 60\,s of clock error, and a degree after four minutes.

\subsubsection{DNS resilience}
\index{DNS}\index{lwIP}

lwIP keeps one process-wide resolver list rather than one per interface, and bringing the WiFi AP up clears it. The firmware caches the resolver address supplied by DHCP and restores it whenever it finds the list empty. \texttt{/network} reports \texttt{dns\_after\_eth}, \texttt{dns\_after\_wifi}, \texttt{lwip\_dns0} and a \texttt{dns\_restores} counter; \texttt{dns\_after\_wifi} reading \texttt{0.0.0.0} and a slowly climbing restore count are both expected, not faults.

\subsection{HTTP API}
\index{HTTP API}

The full endpoint list is in Appendix~\ref{app:api}. The endpoints that carry frame semantics are worth stating here.

\begin{description}[style=nextline]
    \item[\texttt{/status}] \texttt{alt} and \texttt{az} are the Due's \emph{drive} position --- the scheduler's slew-completion check and \texttt{sun\_scan.py}'s record of where a source was found both need that frame, and both compare against a drive target. \texttt{true\_alt} and \texttt{true\_az} are the sky position it corresponds to, and it is those, not the drive position, from which RA/Dec and galactic $l$, $b$ are computed. Converting the drive position straight to RA/Dec would be wrong by the whole calibration. The response also carries \texttt{pointing\_loaded}, \texttt{clock\_state}, \texttt{clock\_age\_s}, and the \texttt{lock\_timeouts} and \texttt{malformed\_status} counters, both of which are zero in normal operation.
    \item[\texttt{/goto}, \texttt{/track/*}, \texttt{/direct}] Targets are true-frame and are rejected below \texttt{horizon\_alt} before any state is mutated. They pass through \texttt{trueToDrive()} before being sent to the Due.
    \item[\texttt{/go-home}] Slews to the stow position. This is the documented exception: stow is already a drive position, so it is sent as it stands and merely clamped to the mount limits. \texttt{state.targetAlt}/\texttt{targetAz} are deliberately \emph{not} written, because those hold a true-frame target and putting drive coordinates in them would be exactly the frame mix the design exists to prevent. \texttt{/home}, by contrast, runs the Due's physical homing sequence.
    \item[\texttt{/pointing}, \texttt{/pointing/apply}, \texttt{/pointing/clear}] The resident pointing model; see Section~\ref{sec:pointing}.
    \item[\texttt{/ping}, \texttt{/network}] Minimal diagnostics, registered ahead of the full UI handler so they answer even if the main page does not.
\end{description}

\subsection{Stellarium protocol}
\index{Stellarium}

The controller implements the Stellarium telescope protocol on TCP port 10001: a 20-byte goto message carrying RA and Dec as unsigned 32-bit fractions, and a 24-byte position report in the same encoding. Reported positions are \texttt{driveToTrue()} images of the measured drive position, so the marker in Stellarium is where the dish is looking rather than where the encoders read.

To configure: Configuration $\rightarrow$ Plugins $\rightarrow$ Telescope Control, enable and restart, add a telescope of type ``External software or remote computer'', host \texttt{192.168.50.120}, port 10001. Select an object and press Ctrl+1 to slew.

\subsection{Tracking}
\index{tracking}

With tracking enabled the controller, once a second:

\begin{enumerate}
    \item Refreshes the target's RA/Dec (every 30\,s for the Sun, Moon and galactic plane; static otherwise)
    \item Converts to true alt/az for the current sidereal time
    \item Tests the true altitude against \texttt{horizon\_alt}
    \item Applies the operator offset and any axis-hold, in the true frame
    \item Converts to the drive frame with \texttt{trueToDrive()}
    \item Tests and clamps against the mount limits
    \item Sends the drive target if it differs from the last one by more than the deadband
\end{enumerate}

\subsubsection{Below-horizon handling}
\index{horizon, observing}\index{stow position}

When the true altitude falls below \texttt{horizon\_alt} the dish parks at the stow position and the controller enters ``waiting for rise''. Position calculation continues each second, and tracking resumes automatically when the target clears the horizon again.

\subsubsection{Azimuth wrap-around and the upper stop}
\index{azimuth wrap-around}

If the drive azimuth falls outside the mount limits --- which happens to circumpolar sources crossing the azimuth dead zone --- the controller enters ``waiting for wrap'', continues computing, and resumes when the target re-enters the range. Note that the rise verdict is settled \emph{before} the transform and the wrap verdict \emph{after} it: clearing the wrap flag in the true frame would announce ``wrap complete'' every second for a target still mechanically unreachable.

Above \texttt{mount\_alt\_max} the mount is simply left where it is. The alternative --- driving to the altitude stop and continuing to track in azimuth --- would run the mount along its limit switch for hours to follow a target it cannot point at.

\subsubsection{Galactic-plane target}
\label{sec:galplane}
\index{galactic plane}\index{galactic plane!acquisition floor}

\texttt{/track/galactic-plane} walks outwards along $b=0$ from the galactic centre in $0.5^\circ$ steps and returns the first longitude whose current altitude reaches \texttt{galactic\_min\_alt}. At each step the two candidates $l = +d$ and $l = 360^\circ - d$ are equidistant from the centre, so the choice between them is free and the higher is taken --- it stays observable longer and looks through less atmosphere.

The $45^\circ$ default floor is an \emph{acquisition} threshold, not a horizon: once acquired the target is followed down until the ordinary observing horizon parks the dish. It is high deliberately. The galactic centre is at $\delta = -28.9^\circ$ and from Glasgow ($\phi = 55.90^\circ$) culminates at
\begin{equation}
h_\text{max} = 90^\circ - |\phi - \delta| = 90^\circ - 84.8^\circ = 5.2^\circ,
\end{equation}
so it never clears the $10^\circ$ horizon --- zero hours in a year. A fixed ``galactic bulge'' button was therefore permanently in fallback. At a $45^\circ$ floor some point on the plane qualifies about 73\% of the time, and never within about $45^\circ$ of longitude of the centre.

\section{Coordinate transformations}
\label{sec:coordinates}
\index{coordinate transformations}
%==============================================================================

\subsection{Reference frame}
\index{J2000}\index{ICRS}

All equatorial coordinates are J2000.0: standard epoch and equinox J2000.0, equivalent to ICRS to within milliarcseconds, and compatible with modern catalogues and with Stellarium.

\subsection{Conversion pipeline}

\begin{equation}
\text{RA/Dec (J2000)}
\xrightarrow{\ \text{precess}\ }
\text{RA/Dec (date)}
\xrightarrow{\ \text{HA}\ }
\text{true Alt/Az}
\xrightarrow[\text{+ model}]{\text{+ refraction}}
\text{drive Alt/Az}
\end{equation}

The first three steps are described here; the last is Section~\ref{sec:pointing}.

\subsubsection{Julian date}
\index{Julian date}

\begin{equation}
\text{JD} = \lfloor 365.25(Y + 4716) \rfloor + \lfloor 30.6001(M + 1) \rfloor + D + B - 1524.5 + \frac{h + m/60 + s/3600}{24}
\end{equation}

with $Y$ the year, $M$ the month (January and February counted as months 13 and 14 of the previous year), $D$ the day, $B = 2 - \lfloor Y/100 \rfloor + \lfloor Y/400 \rfloor$, and $h$, $m$, $s$ UTC.

\subsubsection{Sidereal time}
\index{sidereal time}\index{GMST}\index{local sidereal time}

GMST in hours, by the IAU 1982 expression \cite{aoki}:

\begin{equation}
\text{GMST} = 6.697374558 + 0.06570982441908\,D_0 + 1.00273790935\,H + 2.6\times10^{-5}\,T^2
\end{equation}

where $D_0$ is days since J2000.0 at 0\textsuperscript{h}~UT, $H$ is hours since 0\textsuperscript{h}~UT, and $T = D_0/36525$. Local sidereal time follows as

\begin{equation}
\text{LST} = \text{GMST} + \lambda/15
\end{equation}

with $\lambda$ the observer's longitude in degrees, east positive.

\subsection{Precession}
\index{precession}

IAU 1976 precession \cite{lieske} takes J2000 coordinates to the equinox of date. With $T = (\text{JD} - 2451545.0)/36525$ the angles, in arcseconds, are

\begin{align}
\zeta_A  &= (2306.2181 + 1.39656\,T)\,T + 0.30188\,T^2 + 0.017998\,T^3 \\
z_A      &= (2306.2181 + 1.39656\,T)\,T + 1.09468\,T^2 + 0.018203\,T^3 \\
\theta_A &= (2004.3109 - 0.85330\,T)\,T - 0.42665\,T^2 - 0.041833\,T^3
\end{align}

and the rotation is applied through

\begin{align}
A &= \cos\delta_0 \sin(\alpha_0 + \zeta_A) \\
B &= \cos\theta_A\cos\delta_0\cos(\alpha_0 + \zeta_A) - \sin\theta_A\sin\delta_0 \\
C &= \sin\theta_A\cos\delta_0\cos(\alpha_0 + \zeta_A) + \cos\theta_A\sin\delta_0
\end{align}

giving

\begin{align}
\alpha &= \operatorname{atan2}(A, B) + z_A, &
\delta &= \arcsin C.
\end{align}

\subsection{Horizontal coordinates}
\index{horizontal coordinates}\index{hour angle}

With hour angle $\text{HA} = \text{LST} - \alpha$ and observer latitude $\phi$,

\begin{equation}
\sin h = \sin\delta\sin\phi + \cos\delta\cos\phi\cos\text{HA},
\end{equation}
\begin{equation}
\cos A = \frac{\sin\delta - \sin h\sin\phi}{\cos h\cos\phi},
\qquad
A = \begin{cases}
\arccos(\cos A) & \sin\text{HA} \le 0 \\
2\pi - \arccos(\cos A) & \sin\text{HA} > 0.
\end{cases}
\end{equation}

Azimuth is measured from north through east. This yields the \emph{true} alt/az of Section~\ref{sec:two-frames}.

\subsection{Galactic coordinates}
\index{galactic coordinates}

Using the J2000 galactic pole constants $\alpha_\text{NGP} = 192.85948^\circ$, $\delta_\text{NGP} = 27.12825^\circ$ and $l_\text{NCP} = 122.93192^\circ$,

\begin{align}
\sin\delta &= \sin\delta_\text{NGP}\sin b + \cos\delta_\text{NGP}\cos b\cos(l_\text{NCP} - l) \\
\alpha &= \alpha_\text{NGP} + \operatorname{atan2}\bigl(\cos b\sin(l_\text{NCP} - l),\;
          \cos\delta_\text{NGP}\sin b - \sin\delta_\text{NGP}\cos b\cos(l_\text{NCP} - l)\bigr)
\end{align}

with the inverse used for the $l$, $b$ published in \texttt{/status}.

\subsection{Solar position}
\index{Sun!ephemeris}

Following Meeus \cite{meeus}, with $T$ in Julian centuries from J2000.0:

\begin{align}
L_0 &= 280.46646 + 36000.76983\,T \quad \text{(mean longitude)}\\
M   &= 357.52911 + 35999.05029\,T \quad \text{(mean anomaly)}\\
C   &= 1.914602\sin M + 0.019993\sin 2M + 0.000289\sin 3M \quad \text{(equation of centre)}\\
\lambda_\odot &= L_0 + C \quad \text{(true longitude)}
\end{align}

followed by conversion from ecliptic to equatorial coordinates and precession from the equinox of date back to J2000. Accuracy is about 1 arcminute --- entirely adequate against a $3^\circ$ beam, and the reason the Sun is a usable pointing calibrator.

\subsection{Lunar position}
\index{Moon!ephemeris}

A truncated ELP/MPP02: mean elements $L'$, $D$, $M$, $M'$, $F$, the principal periodic terms in longitude and latitude, geocentric ecliptic to equatorial, then precession to J2000. Accuracy 5--10 arcminutes, comfortably inside the $0.5^\circ$ encoder quantum.

\subsection{Accuracy of the transforms}
\index{accuracy, pointing}

Compared against ERFA/astropy the transforms above agree to better than $0.5$ arcminute RMS in ordinary observing conditions. Residual error is dominated by, in order: the encoder quantum ($0.5^\circ$), the mount pointing model residual (Section~\ref{sec:pointing}), clock error, and only then the transforms themselves. Azimuth becomes ill-conditioned near the zenith, where it is also physically degenerate.

The coordinate and pointing code is exercised on the host by the \texttt{native} PlatformIO environment, which compiles \texttt{coordinates.cpp} and \texttt{pointing.cpp} exactly as they are flashed --- a small \texttt{test/shim/} supplies the little of \texttt{Arduino.h} and \texttt{Preferences.h} that \texttt{pointing.cpp} touches --- rather than testing a copy.

\section{Pointing model and calibration}
\label{sec:pointing}
\index{pointing model}\index{calibration}
%==============================================================================

Everything in Section~\ref{sec:coordinates} produces a position on the sky. This section is about the difference between that and where the mount must actually be driven to see it. The transform lives in \texttt{esp32\_controller\_arduino/src/pointing.\{h,cpp\}}; the measurement of its parameters lives in \texttt{receiver\_scheduler/sun\_scan.py}.

\subsection{Atmospheric refraction}
\index{refraction}\index{refraction!Bennett's formula}

Refraction is applied whether or not a pointing model is loaded, because it is physics rather than calibration. The controller uses Bennett's formula \cite{bennett} scaled for radio wavelengths:

\begin{equation}
R(h) = \frac{1.15}{60\,\tan\!\left(h + \dfrac{7.31}{h + 4.4}\right)} \ \text{degrees},
\label{eq:refraction}
\end{equation}

with $h$ the geometric altitude in degrees. The factor 1.15 accounts for radio refractivity being about 315 N-units against 273 optical, the difference being the water-vapour wet term. A nominal atmosphere is assumed: there is no weather station, and the dry/wet swing is well below the residual of a single calibration scan. The altitude is clipped to $[-1^\circ, 90^\circ]$, and the result forced to zero past the zenith where the tangent's argument exceeds $90^\circ$ and turns negative.

Equation~\eqref{eq:refraction} is duplicated as \texttt{refraction\_deg()} in \texttt{sun\_scan.py} and the two must stay identical. The controller adds refraction to every sky position it converts, so a scan's measured error contains it; the fit removes it before solving, and if it did not, the fitted terms would absorb refraction and the controller would then apply it a second time. At $11^\circ$ elevation that double count is about $0.09^\circ$ --- the same size as the effect the whole calibration is chasing.

\subsection{The model}
\index{pointing model!terms}\index{IE (elevation index error)}\index{IA (azimuth index error)}\index{AN (azimuth axis tilt, north)}\index{AE (azimuth axis tilt, east)}\index{CA (collimation error)}\index{NPAE (axis non-perpendicularity)}\index{TF (tube flexure)}

The mount error is described by the standard alt-az pointing terms\index{pointing model!design} \cite{wallace}. Writing $h$ for altitude and $A$ for azimuth, the correction to be \emph{added} to a true position to obtain the drive position is

\begin{align}
\Delta h &= \text{IE} + \text{AN}\cos A + \text{AE}\sin A - \text{TF}\cos h,
\label{eq:dalt}\\
\Delta A &= \text{IA} + \bigl(\text{AN}\sin A - \text{AE}\cos A\bigr)\tan h
            + \text{CA}\sec h + \text{NPAE}\tan h.
\label{eq:daz}
\end{align}

\begin{table}[H]
\centering
\caption{Pointing model terms}
\begin{tabular}{llp{8cm}}
\toprule
\textbf{Term} & \textbf{Name} & \textbf{Physical meaning} \\
\midrule
IE & Elevation index error & Zero-point error of the altitude encoder \\
IA & Azimuth index error & Zero-point error of the azimuth encoder \\
AN & Azimuth axis tilt, north & Rotation axis tipped towards north; $\text{AN} \approx \delta\phi$ \\
AE & Azimuth axis tilt, east & Rotation axis tipped towards east; $\text{AE} \approx \delta\lambda\cos\phi$ \\
CA & Collimation error & Beam not perpendicular to the altitude axis \\
NPAE & Axis non-perpendicularity & Altitude axis not perpendicular to the azimuth axis \\
TF & Tube flexure & Gravitational droop of the structure \\
\bottomrule
\end{tabular}
\end{table}

The azimuth signs are opposite to the altitude ones for a reason worth remembering: tipping the azimuth axis towards north raises a source in the north but swings a source in the \emph{east} clockwise. The design matrix used by the fit has been checked against numerically rotated horizon coordinates rather than derived on paper alone.

All seven slots always exist and default to zero, so the four-term model actually fitted from Sun data is simply one with CA, NPAE and TF left at zero. A later, richer fit needs no change to the storage, the transform or the wire format.

\subsection{The forward and inverse transforms}
\index{trueToDrive@\texttt{trueToDrive()}}\index{driveToTrue@\texttt{driveToTrue()}}\index{fixed-point iteration}

\texttt{trueToDrive()} applies refraction first and evaluates the model at the \emph{apparent} position:

\begin{align}
h_\text{app} &= h_\text{true} + R(h_\text{true}) \\
h_\text{drive} &= h_\text{app} + \Delta h(h_\text{app}, A_\text{true}) \\
A_\text{drive} &= A_\text{true} + \Delta A(h_\text{app}, A_\text{true}) \pmod{360^\circ}
\end{align}

\texttt{driveToTrue()} inverts this by fixed-point iteration \emph{on the forward transform itself}, so that whatever the forward direction does, the inverse undoes exactly that and the two cannot drift apart. Starting from $(h^{(0)}, A^{(0)}) = (h_\text{drive}, A_\text{drive})$ and writing $F$ for \texttt{trueToDrive},

\begin{equation}
\bigl(h^{(k+1)}, A^{(k+1)}\bigr) = \bigl(h^{(k)}, A^{(k)}\bigr) + \Bigl[\bigl(h_\text{drive}, A_\text{drive}\bigr) - F\bigl(h^{(k)}, A^{(k)}\bigr)\Bigr],
\end{equation}

with the azimuth residual taken the short way round modulo $360^\circ$ so that a guess either side of due north does not chase itself through a full turn. Three iterations are used.

Simply negating the correction evaluated at the drive position is only first-order accurate. That is adequate for the four-term model, but with CA and NPAE present the azimuth correction carries $\sec h$ and $\tan h$, and near the zenith the first-order answer is wrong by about a quarter of a degree --- half the encoder quantum, which is not a rounding error. Three passes bring the error to well under a thousandth of a degree anywhere the mount can point.

\subsection{Guards}
\index{pointing model!clamps}

Two clamps protect the mount\index{pointing model!clamps} from a broken or mis-scaled model. The altitude fed to the $\tan h$ and $\sec h$ terms is limited to $89^\circ$ --- at that altitude $\tan h$ is already 57, far past anything a real term needs, and azimuth is degenerate there anyway. The total correction on each axis is then limited to $\pm10^\circ$; the whole measured error on this mount is around two degrees, so anything beyond that is not a pointing term. Clamping is silent by design, because the model is still reported by \texttt{/pointing} and a model that hits the clamp is therefore visible without a slew having to be commanded from it.

\subsection{Where the calibration lives}
\index{NVS!pointing namespace}\index{pointing model!persistence}

The model is held in the controller's own NVS namespace, separate from the settings namespace on purpose: the calibration is a measurement, not a preference, and ``reset settings to defaults'' must not silently discard it. An absent or malformed record leaves the identity transform --- never a guess.

This replaced an earlier scheme in which the model was smuggled to the controller as a fictitious observer latitude and longitude plus a write to the operator's pointing-offset boxes. That had two failure modes. The web UI reported a location the telescope is not at, and the offset half lived in RAM only, so every reboot silently discarded half the model: measured on 2026-08-19, the azimuth error that reappeared after a power cycle was $1.97^\circ$ against a stored offset of $1.98^\circ$, about a quarter of the signal, lost without a word. The observer position is now the true site position and \texttt{/pointing/apply} does not touch it.

\subsection{Measuring the model: the Sun scan}
\label{sec:sunscan}
\index{Sun scan}

A single scan is an $n \times n$ raster (default $5 \times 5$ at $1.5^\circ$ spacing) centred on the computed position of the Sun, measuring broadband power at each point.

\subsubsection{Raster geometry}
\index{raster scan}\index{cross-elevation}

Offsets are specified on the sky.\index{cross-elevation} An altitude offset is applied directly; a cross-elevation offset $\Delta x$ must be expanded into mount azimuth by the usual $\cos h$ factor:

\begin{equation}
h_\text{cmd} = h_\odot + \Delta h,
\qquad
A_\text{cmd} = A_\odot + \frac{\Delta x}{\cos h_\odot},
\end{equation}

clamped to the usable azimuth range, with the Sun's position recomputed before each point so the raster does not smear as the Sun moves through it. Scans are refused within about $0.6^\circ$ of the zenith, where $\cos h_\odot$ makes the expansion meaningless.

\subsubsection{Beam fit}
\index{Gaussian fit}\index{FWHM}

A circular two-dimensional Gaussian is fitted to the measured power over the offset grid,

\begin{equation}
P(x, y) = a\,\exp\!\left(-\frac{(x - x_0)^2 + (y - y_0)^2}{2\sigma^2}\right) + c,
\end{equation}

whose centroid $(x_0, y_0)$ is the pointing error of that scan and whose width gives the beam
\begin{equation}
\text{FWHM} = 2\sqrt{2\ln 2}\;\sigma \approx 2.3548\,\sigma.
\end{equation}
The covariance returned by the fit supplies the per-scan centroid uncertainties, typically around $0.04^\circ$, which become the weights in the model fit below.

\subsubsection{The datum: an absolute (T, D) pair}
\index{datum, absolute (T, D)}\index{record version}

Each scan point records the Sun's true position $T$ at that moment and the \emph{reported drive position} $D$ the mount actually settled on. The scan datum is their difference:

\begin{equation}
\Delta h = h_D - h_T,
\qquad
\Delta x = \bigl[(A_D - A_T + 180^\circ) \bmod 360^\circ - 180^\circ\bigr]\cos h_T.
\end{equation}

This pair is model-free. Whatever pointing model happened to be loaded during the scan only decided where the raster was aimed, and cancels out of the difference. That is what makes every fit \emph{absolute} rather than a delta composed onto whatever came before, and it removes an entire class of composition error.

It also removes a noise floor. Because $D$ is the position the Due rounded to and actually drove to, rather than the float the scheduler requested, the encoder grid is part of the measurement rather than an unmodelled $0.5^\circ$ uncertainty sitting on top of it; the old quantisation term of $0.144^\circ$ added in quadrature to every scan sigma is gone.

Scan records carry \texttt{record\_version} (currently 2). Version 1 records were residuals against a model that is no longer knowable, and are skipped by the fit with a log message rather than silently pooled.

\subsection{Fitting the model}
\index{least squares}\index{least squares!weighted}

\subsubsection{Design matrix}
\index{design matrix}

For $N$ scans the four fitted parameters are $\mathbf{x} = [\text{IE}, \text{IA}, \text{AN}, \text{AE}]^\mathsf{T}$ and the design matrix $\mathbf{M}$ is $2N \times 4$: rows $0 \ldots N-1$ are the altitude equations~\eqref{eq:dalt} and rows $N \ldots 2N-1$ the azimuth equations~\eqref{eq:daz}, i.e.

\begin{equation}
\mathbf{M} =
\begin{pmatrix}
1 & 0 & \cos A_i & \sin A_i \\[2pt]
0 & 1 & \sin A_i \tan h_i & -\cos A_i \tan h_i
\end{pmatrix},
\qquad i = 1 \ldots N,
\end{equation}

stacked altitude block above azimuth block. The observation vector is

\begin{equation}
\mathbf{b} = \bigl[\,\Delta h_1 - R(h_1),\ \ldots,\ \Delta h_N - R(h_N),\ \Delta x_1,\ \ldots,\ \Delta x_N\,\bigr]^\mathsf{T},
\end{equation}

with refraction subtracted from the altitude half only --- refraction is vertical to first order, so the cross-elevation errors are untouched.

\subsubsection{Weighted solution}
\index{covariance}\index{reduced chi-squared}\index{parameter significance}

With $\sigma_j$ the per-scan centroid uncertainty for observation $j$ and $\mathbf{W} = \operatorname{diag}(1/\sigma_j)$, the fit minimises

\begin{equation}
\chi^2 = \bigl\|\mathbf{W}(\mathbf{M}\mathbf{x} - \mathbf{b})\bigr\|^2
\end{equation}

by least squares, giving residuals $\mathbf{r} = \mathbf{b} - \mathbf{M}\mathbf{x}$, per-axis RMS residuals, and

\begin{equation}
\chi^2_\nu = \frac{1}{2N - 4}\sum_j \left(\frac{r_j}{\sigma_j}\right)^2 .
\end{equation}

The parameter covariance is

\begin{equation}
\mathbf{C} = \bigl(\mathbf{M}^\mathsf{T}\mathbf{W}^2\mathbf{M}\bigr)^{+}\;\max\bigl(\chi^2_\nu,\,1\bigr),
\end{equation}

and the significance of each parameter is $|x_i| / \sqrt{C_{ii}}$. The floor of 1 on the chi-squared scale factor is deliberate: mount quantisation error is partly systematic, so mutually consistent scans give $\chi^2_\nu \ll 1$, and scaling the covariance by it would shrink the parameter errors and overstate the very tilt significance that gates a weak calibration.

\subsubsection{Geometry and quality gates}
\index{quality gates}\index{azimuth coverage}\index{condition number}

A fit is refused, with a message saying what to collect instead, unless all of the following hold. Azimuth coverage is measured as $360^\circ$ less the largest gap in the sorted scan azimuths, which is the quantity that actually determines whether $\cos A$ and $\sin A$ are separable.

\begin{table}[H]
\centering
\caption{Calibration acceptance criteria}
\label{tab:calgates}
\begin{tabular}{llp{7.2cm}}
\toprule
\textbf{Quantity} & \textbf{Requirement} & \textbf{Why} \\
\midrule
Valid scans $N$ & $\ge 4$ & Four parameters need two scans in principle; four spread scans are needed to detect poor geometry and give meaningful uncertainties \\
Azimuth coverage & $\ge 30^\circ$ & Below this the two tilt terms are degenerate with the index errors \\
Condition number & $\le 10^4$ & Direct test that all four parameters are separable \\
Sun altitude & $0^\circ \le h_\odot < 89.5^\circ$ & $\tan h$ diverges at the zenith \\
Min.\ tilt significance & $\ge 3\sigma$ & Geometry only says the parameters are separable, not that a tilt was measured \\
Reduced $\chi^2$ & $\le 4$ & Residuals far above the scan uncertainties mean something other than mount tilt is moving the pointing \\
\bottomrule
\end{tabular}
\end{table}

The last two are checked again at \emph{apply} time, not just at fit time, and a saved model that predates those checks is rejected rather than pushed.

\subsection{Wire format and application}
\index{pointing model!wire format}

The scheduler builds the document with \texttt{pointing\_model\_document()} and POSTs it to \texttt{/pointing/apply}. It deliberately carries the fitted terms and nothing derived from them:

\begin{lstlisting}[language=bash,caption={Pointing model document}]
{
  "version": 1,
  "fitted_utc": "2026-08-19T13:41:02Z",
  "n_scans": 7,
  "frame": "cross_elevation",
  "terms": {"IE": -0.7213, "IA": 1.9842, "AN": 0.3117, "AE": -0.1042},
  "site": {"lat": 55.902426, "lon": -4.307865},
  "residual_rms_deg": {"alt": 0.06, "xel": 0.08}
}
\end{lstlisting}

Unknown term names are ignored, so a richer model can be pushed to older firmware without bricking pointing. A missing \texttt{version} or a malformed number rejects the \emph{whole} document and leaves the current model untouched --- a half-applied model is worse than none. On success the controller replaces the model under the cross-task lock, writes it to NVS outside the lock, and returns the stored model for confirmation.

\texttt{/pointing/clear} zeroes the model and erases the NVS keys. A cleared model and an all-zero model behave identically --- both are the identity transform --- so it is safe to use after mechanical work without leaving pointing in a special state.

\subsection{Operating procedure: a calibration day}
\label{sec:calday}
\index{calibration day}

\begin{enumerate}
    \item Ensure the receiver is free: a Sun scan and a calibration day both claim the SDR and will refuse to start if an observation or a manually booted receiver holds it.
    \item Start a calibration day from the scheduler (\texttt{POST /api/calday/start}) with a scan interval, typically 30 minutes. It waits for sunrise if necessary, runs a scan every interval while the Sun is above $5^\circ$, and finishes at sunset.
    \item Each hardware scan re-homes the mount first, so every datum is referenced to a freshly measured physical limit. A rejected scan is re-homed and retried once; only the final outcome counts as a failure.
    \item Run for a full day, or at least a morning \emph{and} an afternoon set. This is what produces the azimuth spread the tilt terms need; an afternoon-only set will fit and then be refused at the significance gate.
    \item Fit with \texttt{POST /api/calday/fit}. This writes \texttt{pointing\_model.json} and a four-panel \texttt{calibration\_day.png} showing measured against modelled errors in both axes, the residuals, and a summary.
    \item Apply with \texttt{POST /api/calday/apply}. The gates of Table~\ref{tab:calgates} are enforced here before anything reaches the telescope.
    \item Verify: \texttt{GET /pointing} on the controller should return the same terms, and they must survive a power cycle.
\end{enumerate}

After mechanical work on the mount, clear the accumulated scan data (\texttt{/api/calday/clear}) as well as the model --- old scans describe a mount that no longer exists.

\subsection{What the link is}

The observatory computer carries a \textbf{second Ethernet card}. The controller hangs off it on a private point-to-point link that the host owns completely: it serves the address, resolves names, and routes the link out to the internet. The first card stays on the site LAN and is how people reach the computer.

\subsection{Why}

On the site LAN the controller had whatever address the site handed it, and that address was hard-coded in seven places in the code and twenty-five in the documentation. Every renumbering was a code change. On a private link the address is permanently ours.

No firmware change is needed for any of this. The controller stays on DHCP and its address is pinned by MAC on the host, so nothing on the controller is configured for this link and the whole arrangement reverses by moving one cable back to the site switch. \emph{That reversibility is the point} and should be preserved by anything built on top of it.

The one thing the link breaks, if built carelessly, is time --- and by the argument of Section~\ref{sec:esp32} a clock error is a pointing error, arriving overnight and tedious to diagnose after the fact. Routing the link out is therefore not optional.

\subsection{Address plan}
\index{address plan}\index{IP addresses}

The subnet must avoid the site LAN, \texttt{192.168.4.0/24} (the controller's own WiFi AP) and \texttt{192.168.1.0/24} (common home-router range). \texttt{192.168.50.0/24} is used. Nothing depends on the numbers, but changing them means changing \texttt{DEFAULT\_ETH\_*} in the controller's \texttt{config.h} too.

\subsection{Hardware}
\index{TP-Link TG-3468}\index{network card}

A TP-Link TG-3468: PCIe~x1, Realtek RTL8168, driven by the in-kernel \texttt{r8169} module, so Ubuntu brings it up with no driver install.

Avoid cheap ``Intel I210'' listings\index{counterfeit hardware}. A genuine i210-T1 is the better card in the abstract, but real ones are considerably more expensive than the marketplace listings, and those listings are a well-documented counterfeit market. Counterfeits frequently carry cloned or duplicated MAC addresses --- exactly the failure this design depends on not happening, since the controller's address is pinned by MAC. The link carries a status poll and a coordinate stream and the controller's PHY is 100BASE-TX anyway: buy on driver reliability, not speed.

\subsection{Building the link}
\index{NetworkManager}\index{nmcli@\texttt{nmcli}}\index{DHCP}\index{NAT}\index{dnsmasq}

Do this while the controller is still on the site switch; nothing is at risk until the cable moves.

\begin{lstlisting}[language=bash,caption={Create the shared connection}]
sudo nmcli connection add type ethernet \
    con-name srt-link \
    ifname enp5s0 \
    ipv4.method shared \
    ipv4.addresses 192.168.50.1/24 \
    ipv4.never-default yes \
    ipv6.method ignore
\end{lstlisting}

\begin{description}[style=nextline]
    \item[\texttt{ipv4.method shared}] The important one. It sets the address, enables IP forwarding, installs the NAT rules, and runs a dnsmasq on the interface providing both DHCP and a DNS forwarder --- all four in one setting.
    \item[\texttt{ipv4.never-default yes}] Stops the host routing general traffic down a link with only a microcontroller on the far end.
    \item[\texttt{ipv6.method ignore}] Nothing here speaks IPv6.
\end{description}

The controller's address is then pinned by MAC so it can stay on DHCP:

\begin{lstlisting}[language=bash,caption={/etc/NetworkManager/dnsmasq-shared.d/srt.conf}]
dhcp-host=70:4B:CA:58:59:8B,192.168.50.120,srt-controller
\end{lstlisting}

Shared mode leases from \texttt{.10} upward and a \texttt{dhcp-host} entry takes precedence within that range, so \texttt{.120} is safe. Activation without a cable attached succeeds; the interface stays \texttt{NO-CARRIER} until the controller is moved across, which is normal. Verify with \texttt{sysctl net.ipv4.ip\_forward} (must be 1), \texttt{nft list ruleset | grep -i masquerade}, and \texttt{pgrep -af "dnsmasq.*enp5s0"}.

\subsection{Firewall}
\index{firewall}\index{ufw@\texttt{ufw}}

Note first that \texttt{systemctl is-active ufw} reports ``active'' even when the firewall is not enforcing. \texttt{sudo ufw status} is the real answer.

\begin{lstlisting}[language=bash,caption={Firewall rules}]
sudo ufw limit 22/tcp                         comment 'ssh (rate limited)'
sudo ufw allow in on enp5s0                   comment 'SRT private link'
sudo ufw route allow in on enp5s0 out on eno1 comment 'SRT link NAT out'

sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw default deny routed
sudo ufw enable
\end{lstlisting}

Two of those are non-obvious and both were learned the hard way.

\begin{itemize}
    \item \textbf{\texttt{route allow \ldots out on eno1} is what keeps the controller's clock working.} The default forward policy is deny, which silently blocks the NAT. The controller then never syncs time again and the mount mispoints overnight.
    \item \textbf{\texttt{allow in on enp5s0} is what keeps OTA firmware updates working.} \texttt{espota} sends its invitation\index{espota@\texttt{espota}}\index{OTA updates} to the controller and then expects the controller to connect \emph{back} to the host on an ephemeral port --- a different one every run --- so it cannot be allowed by port number. Without this rule the upload fails with the unhelpful \texttt{No response from device}, because the invitation succeeds and only the callback is blocked. Trusting the link interface as a whole is reasonable: it carries exactly one device, on a subnet this host owns and serves.
\end{itemize}

Nothing needs an inbound rule on the site interface. In particular do not open port 5000 --- see Section~\ref{sec:architecture}.

\subsection{Verification}
\index{verification, network}

\begin{lstlisting}[language=bash,caption={Basic checks from the observatory computer}]
ping -c3 192.168.50.120
curl http://192.168.50.120/ping        # -> ok
curl http://192.168.50.120/network     # eth_ip and the DNS diagnostics
curl http://192.168.50.120/status      # live drive and true alt/az
getent hosts srt-controller.local      # mDNS, needs avahi on the host
\end{lstlisting}

Then the check that is easy to get wrong. \textbf{\texttt{/time/status} reporting \texttt{"source":"NTP"} does not prove the link routes.} The firmware carries a numeric NTP fallback behind the pool name, so the clock syncs whether or not DNS works, and will report \texttt{NTP} on a host that cannot resolve anything at all --- a true statement about the clock and a useless one about the network.

What proves it is a \emph{fresh sync after a reboot}. Reboot the controller (an OTA upload will do), then query \texttt{/time/status}: \texttt{sync\_count} must have reset to 1, confirming a real reboot rather than a stale reading, with a small \texttt{last\_sync\_age\_s}. That combination means SNTP packets left the host, reached a time server and came back.

DNS itself can be confirmed either from \texttt{/network} (Section~\ref{sec:esp32}) or by temporarily adding \texttt{log-queries} to the dnsmasq drop-in and watching for \texttt{query[A] pool.ntp.org from 192.168.50.120} in the NetworkManager journal.

Finish by running one OTA upload deliberately, since that is the operation most dependent on the firewall being right:

\begin{lstlisting}[language=bash]
cd esp32_controller_arduino
~/.platformio/penv/bin/pio run -e wt32-eth01-ota -t upload
\end{lstlisting}

\subsection{Recovery}
\index{recovery}

The controller has independent safety nets, so a wrong address is not a bricking risk:

\begin{enumerate}
    \item Move the cable back to the site switch. Because the controller was never reconfigured, this restores the previous state exactly.
    \item The WiFi AP stays active --- SSID \texttt{SRT\_Controller}, UI at \texttt{http://192.168.4.1} --- regardless of the Ethernet settings.
    \item Invalid static configuration falls back to DHCP, so a malformed address leaves the controller reachable rather than dark.
    \item Last resort is the FT232-and-buttons serial flash at the telescope.
\end{enumerate}

\subsection{What the link deliberately does not do}

Access to the controller from other machines on the site network is \emph{not} set up. The host NATs outbound for the controller; nothing routes inbound. Providing it would need a forwarding rule or reverse proxy, which partly re-exposes the thing the private link exists to protect. Remote use at Acre Road is \texttt{waypipe}\index{waypipe@\texttt{waypipe}} into the observatory computer instead.

The site interface keeps whatever the site gives it. Nothing here depends on its address: the masquerade rule matches on the link subnet, the firewall rules name interfaces rather than addresses, and \texttt{never-default} keeps the link out of the routing decision.

The full build procedure, with the commands in order and the checks between them, is in \texttt{docs/OBSERVATORY\_HOST\_SETUP.md}.

\section{Beam, radiometry and velocity frames}
\label{sec:radiometry}
\index{radiometry}
%==============================================================================

Everything so far has been about putting the beam somewhere. This section is about the beam itself, about what the numbers coming out of the receiver mean, and about the one correction the system deliberately does \emph{not} apply.

\subsection{Beam and aperture}
\label{sec:beam}
\index{beam}\index{beam!FWHM}\index{beam!solid angle}\index{aperture}\index{beam dilution}\index{main-beam efficiency}

The dish is 3.0\,m across and the observing wavelength is
\begin{equation}
\lambda = \frac{c}{\nu_{\text{H\,\textsc{i}}}} = \frac{2.998\times10^8}{1.4204\times10^9} = 0.2111\ \text{m}.
\end{equation}
For a uniformly illuminated circular aperture the half-power beamwidth is
\begin{equation}
\theta_\text{FWHM} \simeq 1.22\,\frac{\lambda}{D} = 1.22 \times \frac{0.2111}{3.0} = 0.0858\ \text{rad} = 4.9^\circ,
\end{equation}
and a realistic illumination taper widens this slightly. This single number sets the scale of nearly every tolerance in the preceding sections:

\begin{itemize}
    \item The $0.5^\circ$ encoder quantum is about one tenth of a beamwidth, so pointing quantisation costs almost nothing in signal.
    \item The residual pointing error after calibration, a few hundredths of a degree, is negligible against it --- but the \emph{uncalibrated} error of about $2^\circ$ is nearly half a beamwidth, which is why the calibration of Section~\ref{sec:pointing} is worth the trouble.
    \item The Sun-scan raster spacing of $1.5^\circ$ is roughly $0.3$ beamwidths, and a $5\times5$ grid spans $\pm3^\circ$, comfortably over the half-power points in both axes --- which is what the Gaussian fit needs to find a centroid.
\end{itemize}

The corresponding beam solid angle for a Gaussian beam is $\Omega_\text{b} \simeq 1.133\,\theta_\text{FWHM}^2 \approx 27$ square degrees. An unresolved source of solid angle $\Omega_\text{s}$ and brightness temperature $T_\text{b}$ is therefore diluted to an antenna temperature
\begin{equation}
T_\text{A} \simeq \eta_\text{mb}\,T_\text{b}\,\frac{\Omega_\text{s}}{\Omega_\text{b}},
\label{eq:dilution}
\end{equation}
with $\eta_\text{mb} \approx 0.7$ a typical main-beam efficiency for a dish of this kind. Equation~\eqref{eq:dilution} is why the Sun is usable as a pointing calibrator: its $0.53^\circ$ disc is only $\Omega_\text{s}/\Omega_\text{b} \approx 0.008$ of the beam, but its 21\,cm brightness temperature is of order $10^5$\,K, so it still arrives as an antenna temperature of order $10^3$\,K --- far above everything else in the sky and unmistakable in a raster. That is the figure the receiver's on-Sun power-bar ceiling (\texttt{CAL\_BAR\_SUN\_K}) is set from.

\subsection{System temperature}
\index{system temperature}\index{noise figure}\index{low-noise amplifier}

The receiver's default blank-sky system temperature is 70\,K, built up as follows.

\begin{table}[H]
\centering
\caption{Blank-sky system temperature budget (\texttt{DEFAULT\_CAL\_TEMP\_K})}
\label{tab:tsys}
\begin{tabular}{lrl}
\toprule
\textbf{Contribution} & \textbf{Temperature} & \textbf{Source} \\
\midrule
Low-noise amplifier & 43\,K & SAWbird+ H1, noise figure $\approx 0.6$\,dB \\
Sky & 10\,K & CMB, atmosphere, galactic background \\
Spillover and feed losses & 17\,K & Ground pickup past the dish edge \\
\midrule
\textbf{Total} & \textbf{70\,K} & \\
\bottomrule
\end{tabular}
\end{table}

The amplifier figure follows from the noise figure in the usual way,
\begin{equation}
T_\text{rx} = T_0\left(10^{F/10} - 1\right) = 290\left(10^{0.06} - 1\right) = 43\ \text{K},
\end{equation}
with $T_0 = 290$\,K the reference temperature. The remaining two terms are estimates rather than measurements\index{spillover}\index{ground pickup|see{spillover}}; a measured $T_\text{sys}$ is what the calibration below is for.

\subsection{The radiometer equation}
\index{radiometer equation}\index{integration time}

The RMS fluctuation in a single spectral channel\index{noise, radiometer} of width $\Delta\nu$ after an integration $\tau$ is

\begin{equation}
\Delta T = \frac{T_\text{sys} + T_\text{A}}{\sqrt{n_\text{pol}\,\Delta\nu\,\tau}},
\label{eq:radiometer}
\end{equation}

where $n_\text{pol}$ is the number of polarisations summed (one, for this receiver). The signal appears in the numerator as well as the system temperature because the source is itself noise: a channel sitting on a bright H\,\textsc{i} line fluctuates more than a channel beside it, and the simulator of Section~\ref{sec:simulator} models exactly this.

As a worked example, at the default settings --- 2.4\,MHz of bandwidth over 4096 channels, so $\Delta\nu = 586$\,Hz --- and taking $T_\text{sys} = 200$\,K on a modest line,
\begin{equation}
\Delta T = \frac{200}{\sqrt{586 \times 60}} = 1.1\ \text{K per channel in one minute}.
\end{equation}
Galactic H\,\textsc{i} at low latitude reaches tens of kelvin, so the line is visible in a single minute; a high-latitude profile of a few kelvin needs tens of minutes, and Equation~\eqref{eq:radiometer} is how that observation is planned.

\subsection{Temperature calibration}
\index{temperature calibration}

Two calibration paths exist, and only one of them is currently automated.

\subsubsection{Single-point blank-sky calibration}
\index{blank-sky calibration}

The receiver GUI offers a one-click calibration: with the dish on blank sky, the mean total power over the sliding window is declared to be the entered temperature, giving a scale factor

\begin{equation}
k = \frac{T_\text{cal}}{\bar{P}} \quad \text{[K per arbitrary unit]},
\end{equation}

after which the total-power chart reads in kelvin and the power bar is re-spanned from just below blank sky (50\,K) to the approximate on-Sun level. The scale is invalidated automatically if the bandwidth or FFT size changes, because those alter the raw power scale. It is a one-point calibration against an \emph{assumed} $T_\text{sys}$, so it fixes the units, not the accuracy. Section~\ref{sec:twopoint} shows how a blank-sky and Sun pair measures the number that is currently typed into that box.

\subsubsection{Noise diode and the Y-factor}
\index{noise diode}\index{Y-factor}\index{calibrator}

The calibrator is a noise diode on GPIO 26 of the Due, switchable from the web UI, the API and the schedule, and its state is recorded both in the HDF5\index{calibrator!recorded in metadata} \texttt{calibrator} attribute and in a \texttt{\_cal} filename suffix. At present the system \emph{records} the diode state and does not derive a gain solution from it. The intended use, when a diode of known excess temperature $T_\text{cal}$ is characterised, is the standard Y-factor:

\begin{equation}
Y = \frac{P_\text{on}}{P_\text{off}},
\qquad
T_\text{sys} = \frac{T_\text{cal}}{Y - 1},
\qquad
T_\text{A} = T_\text{sys}\left(\frac{P_\text{source}}{P_\text{off}} - 1\right).
\end{equation}

Because the diode fires ahead of the low-noise amplifier, the same measurement tracks gain drift through the observation, which the blank-sky method cannot. Interleaving on and off spectra is therefore the upgrade path for absolute work; the metadata needed to do it offline is already being written to every file.

\subsection{Velocity frames --- and the LSR correction the system does not apply}
\label{sec:lsr}
\index{velocity frames}\index{LSR (Local Standard of Rest)}\index{barycentric correction}\index{radio velocity convention}\index{topocentric velocity}

The receiver's spectrum carries a second axis in velocity, computed in the radio convention

\begin{equation}
v = c\,\frac{\nu_0 - \nu}{\nu_0}, \qquad \nu_0 = 1420.405752\ \text{MHz},
\end{equation}

equivalently $1\ \text{km\,s}^{-1} \equiv 4.74$\,kHz at this frequency.

\textbf{That axis is topocentric.} No correction to the Local Standard of Rest is applied, and this is deliberate rather than an oversight: the correction depends on the pointing direction, and the receiver process does not know where the dish is looking. The consequence must be understood by anyone using the data, because it is not small:

\begin{table}[H]
\centering
\caption{Velocity terms between the topocentric and LSR frames}
\label{tab:vframes}
\begin{tabular}{lrl}
\toprule
\textbf{Term} & \textbf{Maximum} & \textbf{Period} \\
\midrule
Earth rotation & $0.46$\,km\,s$^{-1}$ & Daily \\
Earth orbital motion & $29.8$\,km\,s$^{-1}$ & Annual \\
Solar motion towards the LSR apex & $20.0$\,km\,s$^{-1}$ & Fixed per direction \\
\midrule
\textbf{Combined} & $\sim50$\,km\,s$^{-1}$ & $\equiv 237$\,kHz \\
\bottomrule
\end{tabular}
\end{table}

A quarter of a megahertz is a large fraction of a galactic H\,\textsc{i} profile, and the annual term reverses over six months, so uncorrected spectra of the same source taken in different seasons will not superpose.

The correction is applied in analysis. Writing $v_\text{topo}$ for the axis as recorded, $v_\text{bary}$ for the observer's barycentric radial velocity towards the source at the time of observation, and $\hat{n}$ for the unit vector to the source,

\begin{equation}
v_\text{LSR} = v_\text{topo} + v_\text{bary} + \mathbf{U}\cdot\hat{n},
\end{equation}

where $\mathbf{U}$ is the kinematic solar motion, which defines LSRK as 20.0\,km\,s$^{-1}$ towards RA $18^\text{h}$, Dec $+30^\circ$ (B1900). Every quantity needed is in the HDF5 file: the UTC timestamps, the target coordinates and the observer position. In practice $v_\text{bary}$ comes from \texttt{astropy}'s \texttt{SkyCoord.radial\_velocity\_correction("barycentric", \ldots)}, and the apex projection is a single dot product. The reference implementation is \texttt{frame\_offset()} in \texttt{astro\_simulator/astro\_simulator.py}, which converts between the LSR, barycentric and topocentric frames in exactly this way; anything written to correct the observed data should agree with it.

\subsubsection{Runtime behaviour}
\index{radioconda}\index{process lock}\index{CORS}

\begin{itemize}
    \item The scheduler re-executes itself under \texttt{receiver\_python\_path} (radioconda by default) unless it is already running there, so receiver subprocesses always have GNU~Radio available.
    \item It is launched from the desktop \textbf{Start SRT Software} item via the VS~Code workspace \texttt{folderOpen} task, which runs \texttt{start\_scheduler.sh}. That wrapper reuses an already-serving instance rather than starting a second one that would die on the bound port. It is deliberately \emph{not} a systemd service\index{systemd, deliberately not used}: a unit would contend for port 5000 with the task, and the scheduler should not come up unattended.
    \item A manual receiver boot is for warm-up and testing only. Scheduled observations stop it before claiming the SDR, and \texttt{/api/receiver/status} reports whether the running process is manual or observation-owned.
    \item A scheduled observation always wins: it cancels a running Sun scan or calibration day and waits up to \texttt{SUN\_SCAN\_PREEMPT\_TIMEOUT} (600\,s) for the SDR before starting.
    \item \texttt{start\_observation} claims the start briefly under \texttt{process\_lock}, then does the pointing and slew-wait \emph{unlocked} and abortable through \texttt{start\_abort}. Blocking work must not be reintroduced under that lock.
    \item Failed or short-lived starts back off after \texttt{MAX\_START\_FAILURES} (3) attempts per schedule slot.
    \item CORS is restricted to the configured controller origins, so the scheduler buttons embedded in the controller's own page work only if \texttt{srt\_controller\_url} and its fallbacks match the origin that page is served from.
    \item \texttt{POST /api/config} accepts only keys already present in the default configuration, and observation filenames are constrained to stay inside the data folder.
\end{itemize}

\section{Sky simulator}
\label{sec:simulator}
\index{sky simulator}
%==============================================================================

\texttt{astro\_simulator/} predicts what this telescope should see. It is not part of the observing chain, but it is how an observation is planned and how a puzzling spectrum is checked against expectation --- and it can hand its pointing to the real telescope.

\subsection{Sky models}
\index{HI4PI survey}\index{Stockert survey}\index{continuum sky}

Two all-sky datasets back the simulator.

\begin{description}[style=nextline]
    \item[H\,\textsc{i} line] The HI4PI survey \cite{hi4pi}, with a $16.2'$ beam and 1.29\,km\,s$^{-1}$ channels --- far finer than the $4.9^\circ$ beam of Section~\ref{sec:beam}, so the simulated spectrum is a genuine beam-weighted average of the survey brightness temperature rather than an interpolation.
    \item[1420\,MHz continuum] The Stockert/Villa-Elisa survey \cite{stockert}, on the same grid, with the zero level (CMB plus isotropic, $\approx 3.2$\,K) stored separately and the strong sources --- Cygnus~A, Cassiopeia~A, Taurus~A --- removed for analytic re-insertion, because they are saturated or blanked in the survey itself.
\end{description}

The full HI4PI cube is 33\,GiB.\index{HI4PI survey!compact cube} The repository ships a compact form of about 23\,MB, block-averaged to $0.5^\circ$ pixels, smoothed to $1^\circ$ total resolution, trimmed to $|v| \le 470$\,km\,s$^{-1}$, thresholded at $3\sigma$, quantised to 0.01\,K in \texttt{int16} and LZMA-compressed. It is exact to better than 0.5\% for beams of $1.6^\circ$ and above, which covers every dish this simulator is meant for; the full cube is fetched from CDS only if a request falls outside what the compact data can honour.

\subsection{Realise}
\index{Realise button}

The \emph{Realise} button hands the simulation to the telescope\index{Realise button}. In spectrum mode it starts galactic tracking of the current pointing (\texttt{/track/galactic}); in drift mode it cancels tracking and parks the dish at the drift-scan start position (\texttt{/direct}), so that the target transits the beam centre half a scan later. It refuses if the resulting position is below the horizon.

This is the only path by which the simulator commands hardware, and it uses the ordinary controller API described in Appendix~\ref{app:api} --- there is no private channel.

\section{Operation}
\label{sec:operation}
\index{operation}
%==============================================================================

\subsection{Startup sequence}
\index{startup sequence}

\begin{enumerate}
    \item Power on the Arduino Due and the controller.
    \item The Due zeroes its current sensors, then runs the three-phase homing sequence of Section~\ref{sec:homing}, finishing at the configured home position and reporting \texttt{Ready}. Allow 30--60\,s.
    \item The controller brings up Ethernet, obtains its pinned DHCP address, starts the WiFi AP, loads the settings and the stored pointing model from NVS, and begins SNTP.
    \item Confirm on the web interface that the clock has synced and that the pointing model is loaded (\texttt{pointing\_loaded} in \texttt{/status}).
\end{enumerate}

A controller that comes up with no pointing model is not broken --- it applies the identity transform plus refraction --- but it will point about two degrees off, which is most of a beam width.

\subsection{Reaching the web interface}
\index{web interface}

Normally, from the observatory computer, either \texttt{http://192.168.50.120/} or the mDNS name \texttt{http://srt-controller.local/}.

If that fails, connect to the WiFi network \texttt{SRT\_Controller} with password \texttt{radio1420}, and browse to \texttt{http://192.168.4.1}. The AP is up regardless of the Ethernet configuration and is the standing way back in.

\subsection{Observing}
\index{observing}

\begin{enumerate}
    \item Enter the target: RA (0--24\,h) and Dec ($-90$ to $+90^\circ$); galactic $l$ (0--360$^\circ$) and $b$; or alt/az.
    \item ``Track'' for continuous tracking, ``Go To'' for a single slew.
    \item One-click targets are provided for the Sun, the Moon, the galactic plane (Section~\ref{sec:galplane}) and stow.
    \item Watch the status readout: it shows the drive position, the true sky position it corresponds to, the derived RA/Dec and $l$, $b$, and whether the mount is slewing.
\end{enumerate}

Targets below the observing horizon are refused outright; a tracked target that sets parks the dish at stow and resumes automatically on rising.

\subsection{Safety features}
\index{safety features}

\begin{itemize}
    \item \textbf{Two-tier position limits} --- software limits inside the physical stops, with a bounded transient tolerance
    \item \textbf{Current limiting} on the filtered current, with continuously re-tracked zero offsets
    \item \textbf{Stall detection} requiring both a settled drive start and an absence of pulses
    \item \textbf{Fault-flag persistence} filtering, so switching transients do not trip a fault
    \item \textbf{Pointing-correction clamps}, so a broken model cannot fling the mount at a limit switch
    \item \textbf{FAULT latching}, requiring an explicit reset
\end{itemize}

\section{The 21\,cm line: expected signals and the temperature scale}
\label{sec:hiastronomy}
\index{H I@H\,\textsc{i} line}\index{21 cm line|see{H\,\textsc{i} line}}
%==============================================================================

Section~\ref{sec:radiometry} established the beam and the units. This section is about the astronomy those units are for: what the 21\,cm line is, what antenna temperature this particular telescope should see from it, what system temperature to expect, and how to measure that system temperature using nothing but the sky and the Sun.

\subsection{The hyperfine transition}
\index{H I@H\,\textsc{i} line!hyperfine transition}\index{spin temperature}

Neutral atomic hydrogen in its ground state\index{neutral hydrogen}\index{hydrogen, neutral|see{H\,\textsc{i} line}} has two hyperfine levels, according to whether the proton and electron spins are parallel ($F=1$) or antiparallel ($F=0$). The splitting corresponds to

\begin{equation}
\nu_0 = 1420.405751768\ \text{MHz}, \qquad \lambda_0 = 21.106\ \text{cm}.
\end{equation}

The transition is magnetic-dipole and strongly forbidden\index{Einstein A coefficient}\index{forbidden transition} \cite{ewenpurcell}: the Einstein coefficient is
\begin{equation}
A_{10} = 2.869\times10^{-15}\ \text{s}^{-1},
\end{equation}
so a single atom radiates about once every 11 million years. It is observable at all only because the Galaxy contains of order $10^{10}\,M_\odot$ of neutral hydrogen, and because collisions keep the two levels close to thermal equilibrium at a \emph{spin temperature} $T_\text{s}$, which in the cold neutral medium tracks the kinetic temperature.

The level populations follow\index{level populations} $n_1/n_0 = 3\exp(-h\nu_0/kT_\text{s})$, and since $h\nu_0/k = 0.068$\,K is far below any astrophysical temperature, the ratio is 3 to within a part in a thousand: three quarters of all H\,\textsc{i} atoms are in the upper state at any time, regardless of temperature. This is why 21\,cm emission measures \emph{how much} hydrogen there is, almost independently of how hot it is.

\subsection{What the line measures}
\index{column density}\index{optical depth}

The observed brightness temperature along a line of sight\index{brightness temperature} is

\begin{equation}
T_\text{B} = T_\text{s}\left(1 - e^{-\tau_\nu}\right),
\end{equation}

and for the optically thin case ($\tau_\nu \ll 1$), which holds for most directions away from the inner Galactic plane, this reduces to $T_\text{B} \approx T_\text{s}\tau_\nu$ and the integral over the line profile gives the column density directly:

\begin{equation}
\left[\frac{N_{\text{H\,\textsc{i}}}}{\text{cm}^{-2}}\right] = 1.823\times10^{18}
\int \left[\frac{T_\text{B}}{\text{K}}\right]\,
\left[\frac{\mathrm{d}v}{\text{km\,s}^{-1}}\right].
\label{eq:column}
\end{equation}

Equation~\eqref{eq:column} \cite{wilsonrohlfs} is the single most useful result in 21\,cm astronomy, and it is the reason spectra must be stored in linear power and calibrated in kelvin rather than decibels: the integral of a logarithm means nothing.

\begin{table}[H]
\centering
\caption{Typical H\,\textsc{i} line parameters for the directions this telescope can reach}
\label{tab:hivalues}
\small
\begin{tabular}{lccc}
\toprule
\textbf{Direction} & \textbf{Peak $T_\text{B}$} & \textbf{$\int T_\text{B}\,\mathrm{d}v$} & \textbf{$N_{\text{H\,\textsc{i}}}$} \\
 & (K) & (K\,km\,s$^{-1}$) & (cm$^{-2}$) \\
\midrule
Inner Galactic plane, $b=0$ & 80--120 & 500--1600 & $1$--$3\times10^{21}$ \\
Outer plane / anticentre & 50--80 & 300--700 & $0.5$--$1.3\times10^{21}$ \\

\bottomrule
\end{tabular}
\end{table}

Two consequences of the $4.9^\circ$ beam\index{beam!averaging over the Galaxy} are worth stating plainly. First, this instrument never resolves individual clouds: it measures the beam-averaged column density over a patch of Galaxy some $5^\circ$ across, which at the distance of the inner Galaxy is hundreds of parsecs. Second, the line profile it records is the superposition of everything along the line of sight, separated only in velocity --- which is precisely what makes the next subsection possible.

\subsection{Galactic rotation and the tangent-point method}
\index{galactic rotation}\index{tangent-point method}\index{rotation curve}

Because the line is intrinsically narrow\index{radial velocity}\index{kinematic distance}, its observed frequency encodes the radial velocity of the emitting gas, and Galactic rotation converts that velocity into position. For gas in circular rotation in the plane at galactocentric radius $R$, observed at Galactic longitude $l$,

\begin{equation}
v_\text{LSR} = R_0 \sin l \left[\frac{V(R)}{R} - \frac{V_0}{R_0}\right],
\label{eq:rotation}
\end{equation}

with $R_0 \approx 8.2$\,kpc\index{Galactic constants $R_0$, $V_0$} the Sun's galactocentric distance and $V_0 \approx 235$\,km\,s$^{-1}$ the local circular speed.

In the first quadrant ($0^\circ < l < 90^\circ$)\index{terminal velocity}\index{Galactic longitude} the line of sight reaches a minimum galactocentric radius, the \emph{tangent point}, at $R = R_0 \sin l$, where the whole circular velocity lies along the line of sight. That gas produces the extreme positive velocity in the profile, and Equation~\eqref{eq:rotation} collapses to

\begin{equation}
V(R_0 \sin l) = v_\text{max}(l) + V_0 \sin l.
\end{equation}

Measuring the terminal velocity $v_\text{max}$ as a function of longitude therefore traces the Galactic rotation curve directly, with no distance ladder and no assumption beyond circular rotation. It is the classic experiment for a telescope of this size, and everything in this document exists to make it possible: the pointing must be good to a fraction of the beam so that $l$ means what it says, the clock must be right so that the alt-az conversion does not smear the pointing (Section~\ref{sec:esp32}), and the velocity axis must be corrected to the LSR (Section~\ref{sec:lsr}) or the derived rotation curve acquires an annual wobble of up to $30$\,km\,s$^{-1}$.

A bandwidth of 2\,MHz spans\index{bandwidth}\index{velocity resolution}\index{channel averaging} $\pm211$\,km\,s$^{-1}$ and the default 2.4\,MHz spans $\pm253$\,km\,s$^{-1}$, comfortably covering the $\pm150$\,km\,s$^{-1}$ that Galactic rotation produces. The default channel width of 586\,Hz is $0.124$\,km\,s$^{-1}$, some eighty times finer than the $\sim10$\,km\,s$^{-1}$ width of a typical line component --- deliberately, because channels can be averaged after the fact but never un-averaged, and smoothing to $10$\,km\,s$^{-1}$ buys a factor of nine in sensitivity.

\subsection{What the telescope collects}
\index{effective area}\index{aperture efficiency}\index{SEFD}\index{sensitivity!K per jansky}

The geometric area of a 3.0\,m dish\index{geometric area}\index{antenna theorem} is $A_\text{g} = \pi D^2/4 = 7.07$\,m$^2$. The effective area follows from the beam through the antenna theorem, $A_\text{e}\Omega_\text{A} = \lambda^2$, with $\Omega_\text{A} = \Omega_\text{MB}/\eta_\text{MB}$:

\begin{equation}
A_\text{e} = \frac{\lambda^2 \eta_\text{MB}}{1.133\,\theta_\text{FWHM}^2}
= \frac{0.04455 \times 0.7}{1.133 \times (0.0858)^2} = 3.74\ \text{m}^2,
\end{equation}

an aperture efficiency of $\eta_\text{A} = A_\text{e}/A_\text{g} = 0.53$ --- a reasonable value for a prime-focus dish with a simple feed, and the number the Sun measurement of Section~\ref{sec:tsysmeasure} can check. The sensitivity in kelvin per jansky is then

\begin{equation}
\Gamma = \frac{A_\text{e}}{2k} = \frac{3.74}{2 \times 1.381\times10^{-23}}
= 1.35\times10^{-3}\ \text{K\,Jy}^{-1},
\label{eq:gamma}
\end{equation}

that is, \textbf{1.35\,mK per jansky}. The reciprocal quantity, the system equivalent flux density, is

\begin{equation}
\text{SEFD} = \frac{2k\,T_\text{sys}}{A_\text{e}} = \frac{T_\text{sys}}{\Gamma}
\approx 5.2\times10^{4}\ \text{Jy} \quad \text{for } T_\text{sys} = 70\ \text{K}.
\label{eq:sefd}
\end{equation}

Fifty thousand janskys is a large number, and it correctly conveys that this is a small telescope: only the handful of brightest radio sources in the sky are detectable at all in continuum.

\subsection{Expected antenna temperatures}
\index{antenna temperature}

For a source small compared with the beam\index{beam coupling factor}, $T_\text{A} = f\,\Gamma S$, where $f$ is the beam-coupling factor. For a uniform disc of angular diameter $\theta_\text{s}$ observed with a Gaussian beam of width $\theta_\text{b}$,

\begin{equation}
f = \frac{1 - \exp\left(-\ln 2 \cdot x^2\right)}{\ln 2 \cdot x^2},
\qquad x = \frac{\theta_\text{s}}{\theta_\text{b}},
\label{eq:coupling}
\end{equation}

which for the Sun or Moon ($\theta_\text{s} = 0.53^\circ$, $x = 0.108$) gives $f = 0.996$ --- a $0.4\%$ correction, negligible beside the other uncertainties but free to apply. For a source that fills the beam, such as the H\,\textsc{i} line itself, the relation is instead $T_\text{A} = \eta_\text{MB} T_\text{B}$.

\subsection{Why only the Sun and Moon can calibrate a \texorpdfstring{$5^\circ$}{5 degree} beam}
\label{sec:confusion}
\index{confusion, background}\index{calibrators!unusable at low resolution}\index{Galactic continuum!as a contaminant}

A source list containing Cassiopeia~A, Cygnus~A and Taurus~A invites the assumption that a small dish has four or five usable calibrators. It does not. At $4.9^\circ$ the beam collects some 27 square degrees of sky, and all three of those sources lie within a few degrees of the Galactic plane, where the diffuse 1420\,MHz continuum is far from negligible. \textbf{Pointing at them measures the Galactic background as much as the source.}

Table~\ref{tab:confusion} makes this concrete, using the Stockert/Villa-Elisa survey that this repository already ships --- with the strong sources removed from it, so the background column is genuinely diffuse emission --- convolved to the telescope's own beam.

The background is between $0.6$ and $0.8$ times the source signal in every case, and the off-position spread --- the part that does not cancel --- runs from $14\%$ of the source for Taurus~A to $190\%$ of it for Cygnus~A, which sits beside the Cygnus~X star-forming complex. Cygnus~A is simply unusable: whichever reference position is chosen, the answer changes by more than the thing being measured. Cassiopeia~A carries a $35\%$ systematic from the same cause, and Taurus~A, at the anticentre, is the least bad of the three at $14\%$ --- still an order of magnitude worse than the $6$--$12\%$ the solar method achieves.

\textbf{The distinguishing property is not brightness, it is whether the background can be removed.} A source fixed on the celestial sphere can never supply a reference measurement of the same piece of sky, because there is no epoch at which it is absent; every off-position is a different patch of Galaxy, and at this resolution those patches differ by a kelvin or more. The Sun and Moon escape by two different routes:

\begin{description}[style=nextline]
    \item[The Sun escapes by brightness] At 677\,K against a background of at most a few kelvin anywhere on the ecliptic, the contamination is below a per cent. No background subtraction is needed at all.
    \item[The Moon escapes by motion] At 1.20\,K the Moon is no brighter than Taurus~A, and on its own that would make it equally useless. But it moves about $13^\circ$ per day --- a beamwidth every nine hours --- so the \emph{same celestial coordinates} can be observed with the Moon in the beam and again once it has left. The background then cancels identically rather than approximately, which is precisely what the fixed sources cannot offer. It is also a black body of known angular size at a physical temperature near 225\,K, so its flux is predictable rather than measured.
\end{description}

Extragalactic source confusion, incidentally, is not the problem here: for a beam this size the classical confusion noise is of order $10^{-2}$\,K, two orders below the diffuse Galactic variation. It is the Milky Way's own emission that spoils these calibrators, not the population of faint sources behind them.

The practical consequence is stated once and applies throughout the rest of this section: \emph{the Sun is the calibrator, the Moon is the independent check, and the fixed radio sources are useful only as tests of gain stability} --- where a repeatable on/off difference matters and its absolute value does not.

\subsection{Measuring the system temperature}
\label{sec:tsysmeasure}
\index{system temperature!measurement}\index{Y-factor}

A total-power measurement gives\index{total power measurement}
\begin{equation}
P = G\left(T_\text{sys} + T_\text{A}\right),
\end{equation}
with two unknowns, the gain $G$ and $T_\text{sys}$, and one equation. \emph{One pointing can never determine the temperature scale.} Every method below is a way of obtaining a second, independent equation, and the differences between them are entirely about what has to be assumed.

\subsubsection{Method A: ambient absorber}
\index{ambient absorber}

The most direct measurement of the receiver alone\index{hot/cold load}. Place microwave absorber at ambient temperature over the feed, then move it aside and look at cold sky:

\begin{equation}
Y = \frac{P_\text{hot}}{P_\text{cold}}
= \frac{T_\text{amb} + T_\text{rx}}{T_\text{cold} + T_\text{rx}},
\qquad
T_\text{rx} = \frac{T_\text{amb} - Y\,T_\text{cold}}{Y - 1}.
\end{equation}

With $T_\text{amb} = 290$\,K and $T_\text{cold} \approx 6$\,K (sky plus atmosphere), a receiver at 43\,K gives $Y = 6.79$. The measurement is accurate and needs no astronomy at all, but note what it does \emph{not} include: the absorber covers the feed, so spillover and ground pickup --- the 17\,K term, and the one most likely to be wrong --- are excluded. It measures $T_\text{rx}$, not $T_\text{sys}$.

\subsubsection{Method B: the Sun, of known flux density}
\index{Sun!as calibrator}\index{solar flux density}\index{RSTN}

This is the method this telescope is built for, since it already knows how to find and scan the Sun (Section~\ref{sec:pointing}). Compare the total power on the Sun with that on nearby blank sky:

\begin{equation}
Y_\odot = \frac{P_\odot}{P_\text{sky}} = 1 + \frac{T_{\text{A},\odot}}{T_\text{sys}},
\qquad
T_\text{sys} = \frac{f\,\Gamma\,S_\odot}{Y_\odot - 1}.
\label{eq:suntsys}
\end{equation}

There is a subtlety here worth extracting, because it decides how much the result can be trusted. Substituting Equation~\eqref{eq:gamma} into~\eqref{eq:suntsys} and comparing with Equation~\eqref{eq:sefd} gives

\begin{equation}
\boxed{\ \text{SEFD} = \frac{f\,S_\odot}{Y_\odot - 1}\ }
\label{eq:sefdsun}
\end{equation}

--- the effective area cancels entirely. \textbf{The Sun measures the SEFD directly, with no assumption about aperture efficiency}, and the SEFD is the quantity that actually sets what the telescope can detect. Converting that to a system temperature in kelvin, by contrast, requires $A_\text{e}$, and it is $\eta_\text{A}$ that carries the largest systematic error in the chain. The honest way to use this measurement is therefore to quote the SEFD as the primary result, and to treat $T_\text{sys}$ and $\eta_\text{A}$ as a pair --- fix either one and the Sun gives you the other.

Four corrections and cautions apply.

\begin{description}[style=nextline]
    \item[The solar flux must be contemporaneous, not assumed] The quiet Sun radiates about $5\times10^5$\,Jy\index{Sun!quiet}\index{Sun!active}\index{solar flux unit}\index{sfu|see{solar flux unit}} (50 solar flux units) at 21\,cm, but an active Sun is ten to a hundred times brighter and varies on timescales of minutes. Fortunately the standard monitoring frequencies include 1415\,MHz --- the RSTN stations and DRAO both publish it daily \cite{rstn} --- which is within $0.4\%$ of the observing frequency, so no spectral extrapolation is needed. Using a nominal quiet-Sun value on a day with an active region is the largest avoidable error in this method.
    \item[Point accurately, and do it after the pointing calibration] A pointing offset $\Delta$ reduces the response\index{pointing error!in calibration} by $\exp(-4\ln 2\,\Delta^2/\theta_\text{b}^2)$, which is $2.8\%$ at $\Delta = 0.5^\circ$ and $11\%$ at $1^\circ$. An uncalibrated mount, mispointing by the $2^\circ$ of Section~\ref{sec:pointing}, would under-read by $40\%$. Better still, use the peak of a Sun raster rather than a single pointing --- the machinery already exists.
    \item[Take the reference close by in both angle and time] The blank-sky reference should be a few degrees off the Sun and taken within a minute or two, so that gain drift, elevation-dependent spillover and atmospheric path all cancel rather than being corrected.
    \item[Correct for atmospheric attenuation] The Sun is attenuated by\index{atmospheric attenuation} $e^{-\tau_0 \sec z}$ on the way in, about $1\%$ at the zenith and $3\%$ at $20^\circ$. Small, but it acts in the same direction as the pointing error.
\end{description}

\subsubsection{The two-point calibration: blank sky and the Sun as loads}
\label{sec:twopoint}
\index{two-point calibration}\index{calibration!two-point}\index{detector offset}\index{linearity}

The $Y$-factor of Equation~\eqref{eq:suntsys} extracts one number, $T_\text{sys}$, from the ratio of two measurements. The same two pointings, treated instead as two \emph{known loads}, do considerably more: they establish the whole power-to-temperature scale, which is what turns the receiver's arbitrary linear units into kelvin.

Write the detected power as a linear response\index{gain, receiver}\index{kelvin scale} to the input temperature,

\begin{equation}
P = g\,T_\text{in} + P_0,
\label{eq:linear}
\end{equation}

with $g$ the gain in units per kelvin and $P_0$ any offset that is present when no sky power is. Blank sky and the Sun give two points on that line:

\begin{align}
P_\text{sky} &= g\,T_\text{sys} + P_0, \\
P_\odot &= g\left(T_\text{sys} + T_{\text{A},\odot}\right) + P_0,
\end{align}

and subtracting removes the offset entirely, leaving the scale factor as a pure difference measurement:

\begin{equation}
\boxed{\ k \equiv \frac{1}{g} = \frac{T_{\text{A},\odot}}{P_\odot - P_\text{sky}}
= \frac{f\,\Gamma\,S_\odot}{P_\odot - P_\text{sky}}
\ \ \left[\text{K per unit}\right]\ }
\label{eq:twopointk}
\end{equation}

The blank-sky level then reads
\begin{equation}
T_\text{sys} = k\left(P_\text{sky} - P_0\right),
\label{eq:twopointtsys}
\end{equation}
and \emph{this} is where the offset matters. Equation~\eqref{eq:twopointk} is immune to $P_0$; Equation~\eqref{eq:twopointtsys} is not, and neither is the $Y$-factor, which tacitly sets $P_0 = 0$. If the detector carries a pedestal --- a spectrometer noise floor, a DC spur at band centre, a quantisation offset --- then the $Y$-factor overestimates the system temperature by exactly $k P_0$. The two measurements alone cannot reveal this; a third point can, and that is the argument for combining methods rather than choosing one.

\paragraph{Worked example.} Suppose blank sky reads $P_\text{sky} = 1.000$ in the receiver's arbitrary units and the Sun raster peak reads $P_\odot = 10.70$, on a day when the 1415\,MHz solar flux is 50\,sfu. Then $T_{\text{A},\odot} = f\Gamma S_\odot = 0.996 \times 1.35\times10^{-3} \times 5.0\times10^5 = 673$\,K, and

\begin{equation}
k = \frac{673}{10.70 - 1.000} = 69.4\ \text{K per unit},
\qquad
T_\text{sys} = 69.4 \times 1.000 = 69\ \text{K},
\end{equation}

assuming $P_0 = 0$. That is the measurement the receiver's calibration box currently \emph{assumes}: its single-point calibration (Section~\ref{sec:radiometry}) asks the operator to type in a blank-sky temperature and derives $k = T_\text{cal}/\bar{P}$ from it. The two-point procedure turns that entry from an input into an output --- the same arithmetic, but with the 70\,K established by observation rather than by a comment in \texttt{b210\_h1\_receiver.py}.

\paragraph{Applying the scale to spectra.} For spectroscopy the two-point result is used in the standard\index{position switching}\index{bandpass correction}\index{on/off ratio|see{position switching}} position-switched form. With $P_\text{on}(\nu)$ on source and $P_\text{off}(\nu)$ on a nearby emission-free reference,

\begin{equation}
T_\text{A}(\nu) = T_\text{sys}\,\frac{P_\text{on}(\nu) - P_\text{off}(\nu)}{P_\text{off}(\nu)}.
\label{eq:onoff}
\end{equation}

This form is worth more than it looks. Dividing by $P_\text{off}(\nu)$ removes the instrumental bandpass --- which is emphatically not flat across 2.4\,MHz --- at the same time as it sets the scale, and being a ratio it is again free of $P_0$ and of any slow change in $g$ between the two. The two-point sky-and-Sun measurement supplies the single number $T_\text{sys}$ that Equation~\eqref{eq:onoff} needs, and nothing else in the chain requires absolute power at all. This is the practical calibration pipeline for this telescope: measure $T_\text{sys}$ against the Sun once per session, then observe H\,\textsc{i} entirely in on/off ratios.

\paragraph{Check the linearity before trusting either.} Blank sky and the Sun differ by a factor\index{automatic gain control}\index{ADC clipping} of about ten in input power, whereas the H\,\textsc{i} line the calibration will be applied to sits within a factor of two of blank sky. A scale derived at the top of that range and applied at the bottom is only valid if the detector is linear across it. Two precautions follow, and both are cheap:

\begin{itemize}
    \item \textbf{Fix the SDR gain and disable any automatic gain control.} The receiver already sets gain explicitly rather than leaving AGC enabled, but a gain chosen for H\,\textsc{i} may put the ADC near full scale on the Sun, and a compressed solar reading inflates $k$ and deflates $T_\text{sys}$. Confirm the Sun measurement is not clipping before using it.
    \item \textbf{Take a third point in between.} It must be one whose input temperature is genuinely known, which rules out the fixed radio sources for the reason given in Section~\ref{sec:confusion}. Two qualify: the Moon\index{Moon!as calibrator} ($\sim1.2$\,K, differenced against the same sky once it has moved on) and the Galactic plane continuum ($\sim5$--$20$\,K, read from the survey and convolved to the beam as in Method~C). Three points falling on a straight line through the origin validate both the linearity and the assumption $P_0 = 0$; three on a straight line with a non-zero intercept give the offset, after which Equation~\eqref{eq:twopointtsys} can be applied properly.
\end{itemize}

Adding the ambient absorber of Method~A as the hot point and blank sky as the cold one gives the same two-point structure with a load whose temperature is known to a fraction of a kelvin rather than to 5--10\%. Its drawback is the one already noted --- it sees no spillover --- so the two calibrations are complementary: the absorber measures the electronics accurately, the Sun measures the whole telescope including everything the absorber bypasses, and the difference between them is an estimate of the spillover term itself.

\subsubsection{Method C: cold sky and the survey slope}
\index{cold sky calibration}\index{Stockert survey!as a calibrator}

The third method uses only the sky\index{sky brightness}, and exploits the fact that the 1420\,MHz continuum brightness is already known everywhere from the Stockert/Villa-Elisa survey. Point at $N$ directions of differing sky brightness and record the total power:

\begin{equation}
P_i = G\left(T_0 + T_{\text{sky},i}\right),
\end{equation}

where $T_{\text{sky},i}$ is the survey brightness \emph{convolved to this telescope's beam} --- which is exactly what the simulator of Section~\ref{sec:simulator} computes --- and $T_0 = T_\text{rx} + T_\text{spill} + T_\text{atm}$ collects everything that does not depend on where the dish points. A straight-line fit of $P_i$ against $T_{\text{sky},i}$ then yields both unknowns at once:

\begin{equation}
G = \frac{\mathrm{d}P}{\mathrm{d}T_\text{sky}}, \qquad
T_0 = \frac{P_\text{intercept}}{G}, \qquad
T_\text{sys} = T_0 + T_{\text{sky}}.
\end{equation}

Its attraction is that it needs no absorber, no ephemeris and no external flux measurement, and that it isolates $T_0$ --- the receiver-plus-spillover term that Method~A cannot reach and Method~B cannot separate. Its weakness is the lever arm: at 1420\,MHz the sky ranges only from about 3.5\,K at the coldest high-latitude minimum to perhaps 30\,K beam-averaged in the inner plane, so a $\sim25$\,K span is being used to calibrate a $\sim70$\,K system. The gain must be stable to a few parts in a thousand across the whole set of pointings, which in practice means taking them within a few minutes and at similar elevations so that spillover does not vary underneath the fit.

\subsubsection{Recommended procedure}

For this telescope, the three methods are complementary\index{calibration!recommended procedure}\index{uncertainty budget} rather than alternative, and the sensible order is:

\begin{enumerate}
    \item Calibrate the pointing first (Section~\ref{sec:calday}). Every method below assumes the beam is where it is thought to be.
    \item Look up the day's 1415\,MHz solar flux.
    \item Run a Sun raster and take the fitted peak, immediately followed by a blank-sky reference $5$--$10^\circ$ away at the same elevation. Repeat three or four times, alternating, over a few minutes.
    \item Compute the SEFD from Equation~\eqref{eq:sefdsun}. This is the primary, assumption-free result.
    \item Take the same pair as a two-point calibration, Equation~\eqref{eq:twopointk}, to obtain the kelvin-per-unit scale $k$ and hence $T_\text{sys}$. Enter that measured value in the receiver's calibration box instead of the assumed 70\,K, and use it in Equation~\eqref{eq:onoff} for every spectrum of the session.
    \item Add a third, intermediate point --- the Moon, Cas~A or the plane continuum --- and confirm the three lie on a straight line through the origin. A non-zero intercept is a detector offset and must be subtracted before Equation~\eqref{eq:twopointtsys}; curvature means the Sun measurement is compressed and the SDR gain must come down.
    \item Run a set of cold-sky pointings spanning as much of the 3.5--30\,K range as the sky allows, and fit for $G$ and $T_0$. This gives $T_\text{sys}$ in kelvin independently of the Sun.
    \item Combine: the two together over-determine the system, and their ratio yields $A_\text{e}$ and hence the aperture efficiency --- a genuine measurement of the antenna, rather than the assumed $0.53$ used throughout this document.
    \item Cross-check against the Moon, not against a fixed radio source. Observe the Moon's position, wait until it has moved a beamwidth --- nine hours, or simply the following night --- and repeat on the same celestial coordinates. The difference is the Moon alone, with the Galactic background subtracted identically rather than approximately, and at a predictable 1.20\,K it is an independent test of the same scale the Sun gave. Section~\ref{sec:confusion} explains why Cassiopeia~A cannot serve here.
    \item Use Cassiopeia~A only as a \emph{stability} test. Repeat the same on/off pair through an observing session: the absolute value is contaminated by the background and means little, but its repeatability at the $0.1$\,K level is good evidence that the gain is steady enough for the H\,\textsc{i} work.
\end{enumerate}

\section{Conclusion}
%==============================================================================

The SRT drive controller is a layered system in which each layer holds exactly one kind of knowledge: the Due knows only pulses and motors, the controller knows the sky and the transform between the sky and the mount, and the scheduler knows what is to be observed and when. The two coordinate frames, and the single file where they meet, are the organising idea; most of the failures worth documenting here have come from mixing them.

Current capabilities:

\begin{itemize}
    \item $0.5^\circ$ encoder resolution with a fitted pointing model that removes the residual mount errors and a refraction correction applied as physics
    \item Absolute, model-free calibration data, so every fit stands on its own rather than being composed onto its predecessor
    \item J2000 coordinates throughout, compatible with modern catalogues and planetarium software
    \item Multiple control paths: web UI, REST API, Stellarium and the scheduler
    \item Automated scheduling, drift scans, satellite tracking and unattended data acquisition
    \item A private, reversible network link that keeps the controller's address and its clock under the observatory's own control
    \item Four hardware-free test paths --- drive simulation, host unit tests, pytest and a Due emulator --- covering everything but the motors
    \item A survey-backed sky simulator that predicts what the instrument should see, and can hand its pointing to the real dish
\end{itemize}

The instrument's principal remaining gap is calibration rather than control: the velocity axis is topocentric and the temperature scale rests on an assumed system temperature. Both are described in Sections~\ref{sec:radiometry} and~\ref{sec:outstanding}, and both are addressed in analysis rather than at the telescope.
